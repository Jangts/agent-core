# 复用证据并核对操作回执

申请写入成功后，客户端可能只看见一个超时。重试前需要分别核对已读证据、原操作回执和客户端交付记录。它们的身份和保留规则各自独立。

## 先问已有事实现在是否仍适用

| 对象 | 绑定身份 | 可复用条件 |
| --- | --- | --- |
| 资料或事实 | 来源、查询范围、版本、观察时间 | 当前仍有权读取且对当前任务有效 |
| 写入回执 | 稳定操作 ID、业务对象与来源 | 业务端口确认相同逻辑操作已执行 |
| 答复交付 | 请求或消息 ID、已保存成果引用 | 当前有权查询并可按交付协议重新发送 |

同一个结果可服务多次说明，仍应检查授权及版本。换一个答案格式只重用事实。请求超时或已确认结果的本地保存失败时，通过业务端口按稳定操作身份核对。

## 用核对结果决定是否继续写入

确认已执行时读回真实成果。业务方明确确认未执行时，在当前授权与原限额下决定是否重试。记录暂时不可见应保留未知状态。核对路径只读，由应用决定人工介入和后续查询。客户端重连时，可查找已授权成果并重新交付已有消息，业务动作保持其原有身份。
