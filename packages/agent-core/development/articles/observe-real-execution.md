# 用运行记录定位第一处错误决定

报告工具显示读取两次，但设计图上的读取节点只有一个。先关联这次请求的运行记录，看看是流程回到同一节点、节点执行了重复调用，还是日志把两次请求并在一起。对应的修复位置各不相同。

## 对照定义、访问和业务回执

检查器的注册图显示允许发生的节点与路由。Engine 的 WorkflowRunTrace 描述本次实际访问和转移，用 run 与 invocation 标识绑定到模型、工具或子任务。节点的 `createStepRecorder` 可记录宿主对局部工作的报告。外部业务效果仍看操作回执。记录缺失时应保留未知状态。

沿访问顺序检查第一处异常。先核对准备阶段和路由条件，再查工具被提议、拒绝还是实际执行，以及交付校验是否触发了重复执行。让日志保留判断用到的事实分类、作用域、耗时及适用的版本。用户内容按授权和保留规则记录，凭据不写入日志。

## 把排查发现转为回归

按[检查器手册](../docs/workflow-inspector.md)导出图或加载已授权的执行记录。定位到“交付失败后重复读取”时，把有效回执放进固定场景，注入失败，断言失败路由和读取次数。用实际模型样本另行验证语义选择。[运行观测合同](../docs/api/observability.md) · [工作流检查 Skill](../skills/agent-core-workflow-inspection/SKILL.md)
