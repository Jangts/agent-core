# 评审分歧并接受现有成果

两份报告分别说同一批次通过与失败。先把两份成果绑定到同一业务范围、内容版本、政策版本和来源，再决定是否发生可比较的分歧。若一份只查了一个样本，另一份查了全部，覆盖差异必须保留。

## 分别记录发现与覆盖

用 `defineResultReview` 登记检测器及其候选范围。检测器只引用候选成果所绑定的证据。确定性检查可识别版本差异，语义检查可由宿主注入有界 Runner。报告同时给出 findings 与 coverage。已确认的一处分歧可以与其他候选尚未检查并存。失败的检测器和未取得的证据应明确呈现。

`checkReviewAdmission` 可检查阻塞项和所需覆盖率，给后续阶段提供预检。决策写入阶段仍应原子地核对来源、政策、当前权限及接受记录。对复杂分歧，可以有限轮数补证，遇到重复或没有进展的结果就停止。

## 让接受动作引用已有成果

用 Review Choice 处理一两份具备明确完整覆盖的现有摘要。缺证据、检查失败或覆盖不完整时，先修复资料。可以发起 Review Decision 等待人工选择。收到回应和显式继续是两次操作。后者才按当前权限接受已验证的答案。提交应绑定等待轮次、答复 ID、来源版本和稳定操作身份。已确认接受应能重复读取回执。接受已有成果本身不增加模型调用。
