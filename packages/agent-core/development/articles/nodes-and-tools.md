# 节点和工具怎样划分职责

客服收到“解释昨晚的服务故障并保存一份记录”。状态查询、原因说明和保存动作的输入、权限与成果各不相同。先写清用户能拿到什么。交付包括服务、观察时间、已确认和未确认的事实，以及保存后取得的回执。

## 在需要分支和恢复的地方设节点

工具负责可授权的业务能力，例如读取监控窗口或创建记录。节点负责推进工作，例如从查询结果确定是否需要读变更记录。授权、参数解析和结果检查随工具注册。工具可以被多个节点调用，节点也可以组合多个工具。把纯字段换算留在程序里。若一项检查需要独立路由、失败处理或可观测的状态，再为它定义节点。

| 组织方式 | 适用条件 | 交接检查 |
| --- | --- | --- |
| 用例式 | 目标已知，整体流程短，主要分支由领域规则决定 | 节点能交付完整结果，恢复不必重复已确认的读写 |
| 探索式 | 证据决定下一步，获取顺序事前难定 | 有可授权的有限动作、进展标记和停止条件 |
| 矩阵式 | 多个决策复用一组生命周期钩子，组合随请求变化 | 每个决策能追到实际启用的工具和钩子 |

## 用一次失败检验边界

在保存已确认后让最终格式检查失败。恰当的边界能把修复送到结果呈现，只读取已有回执。若每个低层函数都变成一个节点，检查跨节点传递的数据量和授权上下文。若所有工作都塞在一个节点，检查失败时能否识别最后一个已确认的成果。

在已安装 SDK 的项目中运行 `node node_modules/@jangts/agent-core/development/docs/examples/lifecycle-matrix.mjs`，对照选定钩子与全组钩子，并观察呈现失败后的保留结果。两种顺序组织可对照[同任务示例](../docs/examples/organization-comparison.md)。[工作流设计 Skill](../skills/agent-core-workflow-design/SKILL.md)
