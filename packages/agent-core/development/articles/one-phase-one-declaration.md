# 从能力目录准备一次模型决策

工单流程有两个模型阶段。第一个阶段可提议查询工单或读变更记录，第二个阶段依据执行回执给出解释。工具目录里即使只有一份定义，如果提示、选择协议和参数校验各自列出能力，两阶段也可能出现过期名称或被误用的写入范围。

## 从目录选出当前阶段的能力

用 `Support.defineToolCatalog` 收纳工具说明、模型可见 schema、实际解析、授权和执行。进入模型决策前，用当前阶段允许的工具构造 `Support.createModelInteraction`。节点只暴露该阶段需要的选择，稳定的应用目标仍可以由更广的领域目录表达。需要在发送前做测量或检查时，通过 Runner 的 `prepare` 持有本次准备句柄。发送时沿用这个句柄，并按其合同传入本次输入。

模型输出中的操作 ID 和参数是提议。用绑定到当前可信请求的工具运行时调用已注册的工具，检查授权并读取 `invoke` 的实际 `value`。授权即使在选择之后才变化，也以实际执行的检查为准。答复阶段只需要执行结果时，就用结果构建输入。

## 把一致性变成可验证的观察

记录发送给 Provider 的工具名称和 schema，断言它们来自同一阶段。用一个受限账号提议已注册工具，断言授权拒绝、业务端口调用为零。再构造一个目录之外的名称，核对它在协议或调度边界被拦截，并保留清晰的拒绝原因。

在已安装 SDK 的项目运行 `node node_modules/@jangts/agent-core/development/examples/model-protocols.mjs`，查看五种协议共享只读工具定义的方式。矩阵案例可以进一步验证阶段和钩子关系。[能力配置](../docs/api/configuration-in-workflow.md) · [工作流设计 Skill](../skills/agent-core-workflow-design/SKILL.md)
