# 同一任务的两种组织方式

[English](organization-comparison.en.md) · [案例索引](../examples.md) · [可运行源码](organization-comparison.mjs)

代表任务是「解释 demo 服务状态并保存答案」。两种方式共用同一组事实（online、12ms、来源 monitor:7、修订 7）、工具、脚本化 Provider、处理函数与交付合同。直接运行已安装包内的文件，不需要凭据、MockGPT、网络或应用数据库：

```sh
node node_modules/@jangts/agent-core/development/docs/examples/organization-comparison.mjs
```

Node 要求与包一致（22.12+）。仓库已有可解析的 Core 构建时，从仓库根运行：

```sh
node development/docs/examples/organization-comparison.mjs
node --test test/reference-organizations.test.mjs
```

## 如何选择边界

| 事项 | 用例节点 `use-case` | 受约束调查循环 `exploration` |
| --- | --- | --- |
| 组织 | 理解目标后，完整「解释服务状态」用例拥有读取、补齐证据、生成解释与提交答案；保存、可选检查、格式修复各有边界 | 单个 Core 节点依据当前证据和未解决问题选择工作，节点内报告实际动作 |
| 拆分理由 | 生成成果、写入回执和附属检查可以单独观察与接管；适合需要独立路由这些责任的宿主 | 当所有阶段共享一个调查生命周期、无需独立路由时，减少节点间合同；适合范围小、动作集合受控的调查 |
| 下一步 | 路由按已知依赖推进，不额外询问模型 | online 无需补读；degraded 读 incident；changing 读 deployment；Core 自循环路由负责调度，没有另建执行器 |
| 交接 | `service → evidence → answer → receipt` 作为节点更新提交 | 同样字段逐次提交；保存补读尝试与写入核实标志，动作由缺口重算，不靠阶段编号推进 |
| 恢复 | 外部宿主可按已提交事实、成果、回执恢复自己的请求状态 | 外部宿主保存证据及尝试记录；从仍未解决的缺口继续，未知写入不重新执行 |

本例探索读取路径由实际证据决定，不是固定阶段数组：在线直接解释，异常状态补读对应来源。一次补读没有新证据就记录缺口、停止调查，保留已知状态；不靠重复调用碰运气。它是有限动作集合的探索参考，不声称提供开放式研究 Agent。未知服务选择交给模型，明确的读取、保存与后续检查由程序推进。真正开放的调查需要 App 另行约束授权动作、证据缺口、进展与终止条件。两种方式都合理；节点多寡不构成质量分数。若无需独立路由，可把可选检查留在交付 handler 内；若循环内部某动作必须独立恢复，也可升为节点。

## 模型判断、状态与副作用

首次模型调用解释服务请求，第二次基于来源与数值解释事实。Provider 被脚本化，不能证明它理解了自然语言；生产 App 必须验证目标与权限，本例仅接受 demo。算数、事实投影、依赖、权限和写入结果核实不交给模型。固定输入省略首次理解也合理，不为凑调用数量保留它。

读取成果只有在同一授权范围、目标、来源修订内才可复用。`cached` 是宿主已经验证这些前提的 fixture，不提供通用缓存判断。`save` 与 `receipt` 均携带同一 scope 和请求键，工具目录在每次实际调用前核对宿主授权范围；回执读取被拒绝或失败也保留答案和 pending。`save` 使用稳定请求键，真实宿主应从请求身份生成键并绑定授权；内存回执表只模拟权威存储，不是持久化方案。已确认回执跳过保存；连接在写入后中断，先读回执，仍未知则保留答案并明确等待核实，不盲重试。

节点返回的更新才会提交；取消会使运行拒绝，不伪装成功，但取消前已提交的答案与回执仍留在 App 状态。Core checkpoint 本身不持久化外部效果，也不撤销已执行写入。跨进程恢复、回执落盘、交付连接故障由宿主负责，案例不宣称已验证。

## 资源与故障

初始模型额度为 1，宿主授权上限为 2。得到有效事实后，生成解释是必要工作，先由公开 `Support.assessModelBudget` 评估剩余一次解释工作，再按 expand 建议使用 `adjustCallBudget` 扩到 2，已消耗次数不重置。硬上限为 1 时，仍可交付带来源的确定性事实并说明叙述未生成；不会把初始额度不足直接当作局部交付理由。

长记录中只删除已知冗余 `noise`，保留服务、状态、数值、来源与修订；原始证据留在状态供回读。这是字段投影，不是语义压缩或模型摘要；本例没有运行摘要模型。它不补造缺失事实；读失败时停在真实缺口。模型生成失败时保留事实交付。可选检查失败只增加说明，保留主答案及回执。最后的格式修复仅接收现有答案，不持有工具或模型上下文；失败保留原答案，不重开写工具。取消在调用边界生效；读取、生成、保存和回执异常分支都先检查取消，不将它包装为局部成功。

脚本输出实际节点访问、模型调用次数、工具顺序、写入次数、预算修订和投影前后字符数。回归还覆盖缺少前提、同范围复用、已确认写入、未知写入可核实/不可核实、模型失败、硬边界和取消。字符数不是 token、账单或性能收益。证据等级仅为静态结构和离线行为；真实模型语义、真实存储、线上恢复与性能均未验证。
