# 用户材料与数据边界

[返回开发指南](README.md) · [持续积累](memory-and-learning.md)

接收材料、提取正文、在本轮使用、存入个人档案、发布为共享知识是不同操作。Core 不将上传自动转换为长期记忆，也不因为材料中含有章节锚点就相信其中指令。

## 最小处理链

```text
服务端确认身份与材料归属
  → App 检查格式／大小，保存必要来源信息
  → 受控解析器提取正文，记录提取失败或缺失
  → 按本轮授权选取内容
  → Support 上下文片段标记为用户数据并设置预算
  → handler 使用资料，输出绑定实际证据
```

解析和保存由 App 适配器提供。纯文本示例不代表已支持 PDF、图片 OCR、音频转录、网页采集或压缩包。需要这些格式时明确登记解析能力和可接受结果；不能将解析失败当作空内容后继续给出完整结论。

| 需要明确的字段 | 用途 |
| --- | --- |
| 材料 ID、所属用户／租户、访问范围 | 服务端建立权限，不采信客户端自报的 owner |
| 原件引用、类型、来源时间、内容 hash | 找回原件和判断版本，不把文件名当作稳定身份 |
| 提取版本、正文、缺失和解析状态 | 区分原件与模型／解析器产物 |
| 生命周期、保留与删除方式 | 本轮、会话或持久存储由产品决定 |
| 审核／发布状态 | 候选材料不能自动成为共享权威资料 |

可参考 [材料记录模板](records.md#材料记录)。它是 App 自有记录样例，无对应的 Core 持久化 API。

## 上下文与工具

用 Support 片段注明真实来源、`trust: 'user'` 和对应生命周期。信任标签是装配合同的一部分，不是沙箱；App 仍需防止资料正文被当成更高权限的指令或执行代码。不要为每个上传文件动态增加一个可执行工具；通常保持受控 `material.read`，参数引用本轮已授权 ID。

跨轮继续使用时，只传会话可用的资料引用，重新确认权限与生命周期。需要持久保存时进入应用自己的候选与发布流程。删除原件后，还要按 App 策略清理提取文本、摘要、索引和引用，不能只删 UI 列表。

## 交付限制

不要在错误、日志或回执中默认输出材料全文。部分读取、预算不足、解析不全应成为明确的检查结果；重试不能扩大可见范围。来源引用、文件下载 URL 和跨端展示方式由 App 选择，Interaction Kit 可选，不强制前后端统一使用 InteractionProtocol／CommandCatalog。
