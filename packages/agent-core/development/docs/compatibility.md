# 版本兼容与维护

Agent Core 的稳定合同包括公开入口、类型、配置、默认行为、结果、错误分类、事件语义及已声明的保存格式。概念名称按长期职责确定，不随实现方式、厂商或流行词变化而反复调整。

## 稳定、实验与内部

| 范围 | 兼容规则 |
| --- | --- |
| 稳定 | 公开文档和包 exports 所描述、未明确标注实验的入口按稳定合同维护。子路径聚合指向同一实现，不产生第二套执行机制。 |
| 实验 | 只有显式标注实验并说明变化范围的合同才属于实验；实验标记不能放松授权、身份、预算或取消保证。 |
| 内部 | 未公开实现细节不承诺稳定。源码文件可读、构建产物可找到或内部路径可解析，不意味着可依赖其私有合同。 |

不能通过事后将公开入口改标内部来逃避兼容责任。普通接口扩展遵循各入口的能力可选性，纯后台或实时 Provider 不必实现无关的生成能力。

## 1.x 合同

稳定接口的破坏性变化原则上进入下一主版本。移除或改名、输入收窄、返回结构改变、默认策略改变、错误分类改变、事件顺序改变，以及要求消费者处理新的联合类型分支，都须评估调用方影响；“新增字段”或类型可编译不能单独证明兼容。

预算、取消、授权、工具结果校验、状态接纳和副作用保证是行为合同。停止等待不等于远端动作撤销；模型提出工具调用不等于获准执行。兼容更新不能暗中改变这些区别。

Deprecated 入口注明替代方式。随 1.0 稳定交付的旧名称兼容入口维护于整个 1.x，移除进入 2.0。它们指向同一规范实现，不构成两套独立行为。0.9 到正式接口的明确类型迁移例外及参数桥接见[升级说明](upgrading.md)。

## 保存格式与宿主

格式版本、定义修订、CAS 修订、操作身份和提交身份分别解释。每个保存格式按自己的读取合同选择保持格式、局部兼容、独立迁移或拒绝；不存在所有记录统一适用的多版本恢复器。Durable 只接受其声明的当前格式，不承诺恢复任意旧版本或任意工作流调用栈。

类型或方法改名不要求改写原存储键、ID、期限、累计额度或已提交回执。历史记录可读也不代表可恢复执行。恢复需重新绑定宿主资源与当前授权，不恢复凭据或旧权限结论。宿主提供存储原子性、主体隔离、保留期和实际外部副作用保证。

## 依赖、外部协议与安全修复

运行环境、依赖及可选 peer 以包清单和相应接口说明为准。可选依赖缺省时，不使用该能力的正常路径仍独立可用；引入依赖或提高环境要求须评估兼容影响。

厂商能力只在明确的协议、端点、模型与生命周期范围内成立。兼容协议不保证所有产品等价，模拟服务、厂商真服务、本机传输与媒体设备的证据不能互相替代。厂商内部不可观察费用、生产容量和可用性不属于本库无限保证。

安全修复若必须改变行为，应说明触发条件、受影响范围、替代方式及版本边界，不静默更改默认授权或重放策略。问题复现宜提供最小公开接口用例、版本、运行环境、错误分类及脱敏诊断；不要提供密钥、凭据或原始私有状态。本政策不承诺固定响应 SLA、支持年限或生产吞吐。
