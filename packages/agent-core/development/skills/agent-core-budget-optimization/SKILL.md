# Optimize an Agent Core model budget

Use the App's installed SDK. Read `development/docs/api/core.en.md` for call accounting and prepared input measurement, `development/docs/api/observability.en.md` for execution evidence, and `development/docs/api/context-processing.en.md` when history or compression is involved.

1. **Establish a baseline by request path.** Gather available authorized execution records for ordinary replies, tool use, long history, and failure or retry cases as relevant. Make a ledger with the run and invocation IDs, node visit and stage, purpose, outcome, elapsed time, measured input size, and provider-reported input/output usage when available. Include retries, fallback, delegation, summarization, and optional generation. Track tool calls separately. Count actual charged attempts once and distinguish preflight rejection. Mark missing usage as unknown.
2. **Remove repeated work first.** Look for repeated reads, schema or context repeated across calls, routine review and rewriting, and metadata generated in separate requests. Reuse a validated read within the same authorized scope, target, version and projection, including an equivalent read in flight. Keep refreshes, writes and incomplete results out of blind reuse. Pass structured outputs between nodes and combine model judgments when they can use the same evidence. Keep independent authorization, required checks and user-requested results intact.
3. **Measure the assembled input.** Use the prepared request's `measure` for message, instruction and schema sizes without making a model call. Send source references and relevant excerpts, keep the latest complete turns and protected input, and retrieve older detail when needed. If compression is worthwhile, use a trigger and a lower target, retain a coverage cursor for incremental updates, and measure both its added call and subsequent input savings. A token estimate, provider usage and billed cost are separate measurements.
4. **Protect completion.** Budget one run across its model stages and child Runners. Set child limits and reserve enough parent calls for the expected user-facing completion path. When the allocation becomes tight, assess remaining necessary work with assessModelBudget: reuse and project evidence, select or compress long context, and adjust the request allocation within the host-authorized ceiling when useful work remains. A low initial quota alone is not a reason for partial delivery; replan first, and deliver partial work only for actual blockers, necessary user input or exhausted feasible alternatives. Preserve valid evidence and an independent model-free recovery path. Bound retries and keep cancellation and remaining deadlines across shared work. Account for charged failures even when usage is unavailable.
5. **Verify the proposed savings.** Use offline scenarios to assert route, call count, recovery and completion contracts. Use comparable authorized real-model samples to compare semantic success, input/output usage, calls and latency. Keep use cases, model settings, fixtures and grading aligned, or state the differences. Record permission and side-effect behavior alongside the savings.

Deliver the baseline ledger, the largest avoidable cost with its evidence, the proposed changes and reserves, and the before/after checks. With static evidence only, identify what to measure and describe savings as a hypothesis.

Read [reasonable dynamic budgets](../../articles/reasonable-dynamic-budgets.en.md) and [compression versus partial delivery](../../articles/compression-or-partial.en.md) before proposing a lower limit.

Choose projection, reuse, compression, allocation expansion and partial delivery as separate decisions. Estimate remaining necessary calls numerically and distinguish remaining calls from the total allocation including consumption. Compare compression cost plus later savings with projection-only input for the same task; preserve corrections, authority, critical values, receipts and source retrieval. Fixed budgets remain suitable for uniform paths. Neither a low initial allocation nor a static warning justifies abandoning feasible work.

Use [the complete organization example](../../docs/examples/organization-comparison.en.md) to trace initial allocation, charged attempts, justified expansion and the hard-ceiling alternative. Follow the current source and regression rather than inferring costs from the graph. Its deterministic evidence projection illustrates removing redundant input without a summarizer; use representative model samples separately when assessing summary fidelity or billed savings.
