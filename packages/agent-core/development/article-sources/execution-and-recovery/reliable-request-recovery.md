# 请求失败后交付已经确认的结果

用户请求保存报告并收到说明。保存已经成功，生成说明时模型超时。业务记录和答复是两个结果。恢复可以复用确认回执，说明保存成功，并指出仍缺少详细说明。

## 为不同失败指定处理范围

| 处理位置 | 可以做的工作 | 需要读到的状态 |
| --- | --- | --- |
| 工作流失败路由 | 定向补证、改写或修复格式 | 当前节点与已有结果 |
| 请求恢复 | 从已确认的成果组织可用答复 | 稳定的成果 ID、回执与真实缺口 |
| 本地收尾 | 程序化返回状态或交代不能确认的事项 | 已确认事实和失败种类 |

用 `Support.createRequestRecovery` 将 `execute`、可选的 `recover` 和同步 `fallback` 绑定到同一记录。执行只进入一次。恢复失败时回到本地收尾，原执行与恢复错误保留给诊断。回执应在其确认时写入记录，确保后续异常仍能读到。

## 把超时、取消与传输断开分别处理

执行专用超时放在 `execute` 内部，给请求恢复保留自己的有限时间。用户明确取消时将取消传播到调用链，恢复和程序收尾不会被用来重启任务。断连时，服务器若已持久化成果，可以在重连后按当前授权查询。写入结果不明时走[回执核对](evidence-and-operation-receipts.md)。
