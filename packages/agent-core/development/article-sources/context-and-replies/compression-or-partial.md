# 控制输入长度与交付范围

用户要求对照完整的两个商品集合，当前请求已经查到共同 ID，但原始记录让下一次模型调用超出容量。可先在程序中计算差异，再只提供差异与必要的证据。用户要的完整结论仍然可以提供。

## 优先缩小当前调用所需输入

| 情况 | 处理 | 需要保留 |
| --- | --- | --- |
| 材料很长，字段用途已知 | 程序投影、聚合或分段读取 | 来源 ID、版本和可回查范围 |
| 旧对话长，近几轮决定当前含义 | 保留完整近期轮次，按需为早期历史成稿 | 最新纠正、待确认问题、原始引用 |
| 摘要可能改变数字或资格条件 | 回读原文，使用结构化事实 | 数量单位、条件、例外、权限 |
| 必需来源拒绝访问或持续不可用 | 明确已验证的范围与欠缺 | 获授权的成果和未完成原因 |

`Support.createContextProcessingNode` 按应用声明的策略处理上下文计划。先判断有无必要重读或投影，再决定是否为摘要分配额外模型调用。可信指令和策略保护的片段保持其原有边界。摘要继承原数据的信任限制。压缩完成后，用返回的准备句柄测量并发送实际调用所需内容。

## 有明确阻塞时收束交付

如果价格源无权限，可以交付已验证的目录差异，并明确价格未核对。若缺一项条件就会使整个结论无法使用，先澄清或请用户补充。把上下文大小、调用额度与事实缺口分别记录，便于其后补查资料或调整预算。
