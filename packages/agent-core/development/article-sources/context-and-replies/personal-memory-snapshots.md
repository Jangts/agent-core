# 用证据维护个人记忆快照

用户今天说“以后用简短答复”，上周又说“技术评审要写清依据”。当前请求如果明确要求详细说明，就按这次的要求回答。长期偏好可以给后续默认值，具有期限的目标可以提示尚未完成的事。两者都要带上来源和适用范围。

## 从授权来源生成候选更新

应用先按账号、会话、已完成状态、保留政策筛选来源。后台提取模型只提出候选，通过 `memoryUpdateSchema` 解析。应用再检查语义、敏感信息和真实归属。Kit 用源 ID 与用户原文的精确引文核对证据，保存证据引用并丢弃引文。是否代表长期偏好、是否为角色扮演或只是引用他人的话，需要另行判定。

从版本化快照开始，用 `applyMemoryUpdate` 生成新快照。来源分批可以用 `batchMemorySources`，同时间戳组完整保留。应用可提供稳定顺序的 `orderKey`，处理同毫秒的纠正。没有可确认顺序时保留已有项。发布时在同一事务比较版本并推进已处理水位。版本冲突后读取当前快照再计算。提取或提交失败时，保留原水位以便重试。

## 控制读取、撤回与重新检查

`memoryContext` 提取有界偏好和相关项，并维持会话范围。当前用户指令优先。过期目标、已撤回条目和待复核项退出自动使用。历史遗留摘要单独作为未验证信息，以固定日期退出兼容路径。来源删除后由应用决定撤回或排除相关条目，并将可用性送入复核，调用 `reviewMemorySources` 等接口安排有限的检查。工具授权、身份和已执行事实仍来自当次业务端口。
