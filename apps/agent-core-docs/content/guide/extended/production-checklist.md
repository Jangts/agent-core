# 上线前的软性检查

这份清单检查“是否准备好了”，不替代[接入检查](/manual/acceptance)的硬验收。硬验收证明接口和边界按合同工作；软检查确认你把它们放进了真实业务，并且能解释结果从哪里来、失败时退到哪里。

每项都应留下证据：日志、评测结果、配置差异或一次真实调用。没有证据的项目不要标记为完成。

## 资料与权限

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 资料目录可加载，空资料有明确状态 | 启动日志或自检结果 | 修加载路径，不把空资料当正常 |
| 文档、章节与块 id 唯一，revision 非空 | 校验输出 | 修数据，不跳过校验 |
| 权限过滤使用可信身份 | 代码路径与一次越权测试 | 在融合或读取前补过滤 |
| 删除与改版会同步清理索引和引用 | 一次删除或改版演练 | 补清理流程，不只改列表 |

## 配置与版本

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 生效配置有版本标识并进入日志 | 一条请求日志 | 补标识，不使用“当前配置”这种模糊说法 |
| 资料源与运行副本一致，没有手改运行目录 | 生成或比对结果 | 回到源稿修改并重新生成 |
| 密钥来自环境或密钥服务 | 配置检查 | 移出仓库与资料文件 |
| 模型、embedding 与索引空间标识一致 | 启动自检 | 重建索引或修正配置 |

## 预算与能力

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 正常请求不会偶发预算拒绝 | 真实样本的字符统计 | 留余量或分次读取 |
| 超限时按合同拒绝或交付已确认的范围 | 一次超限调用及其交付 | 保留必须的来源，说明实际限制 |
| 动态扩额保留消耗、硬上限与上游预留 | 同一请求调配前后账本及上限拒绝用例 | 按请求绑定调整分配 |
| 重试有次数与总期限 | 失败注入结果 | 加边界与退避 |
| 取消后停止后续调用 | 一次取消测试 | 每层检查并传播 `signal` |

## 检索与引用

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 真实问题上的来源命中达到预期 | 小样本评测结果 | 先改切块、词表或章节结构 |
| 没有资料时明确说不知道 | 无答案样本结果 | 修判定与提示边界 |
| 引用指向真实来源且与正文一致 | 抽查回答与来源 | 回源复核 revision 与可见性 |
| 检索失败与“没有资料”分开处理 | 降级日志 | 区分两种状态 |
| 索引更新不会返回已删除内容 | 删除后的一次查询 | 清理索引与缓存，复核可见性 |

## 失败路径

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 模型限流、超时、鉴权失败有明确行为 | 失败注入记录 | 补分类与处理策略 |
| 写入确认丢失时按稳定操作身份只读核对 | 在业务写入后注入回包丢失，检查实际写入次数和回执 | 保留未知状态并接入业务回执查询 |
| 已确认成果在文案修复失败或重连后仍可查 | 保存成功后注入交付失败，验证结果查询及当前授权 | 分别记录业务回执和消息交付 |
| 启用审批或持久任务时，继续执行使用当前授权与原截止时间 | 重建进程后验证过期、权限撤回及重复提交 | 重新核对绑定、来源与持久账本 |
| 依赖不可用时降级或明确失败 | 一次降级演练 | 去掉“假装成功”的兜底 |
| 降级不扩大权限 | 越权路径测试 | 移除绕过校验的分支 |

启用个人记忆时，用双账号、不同会话、过期及删除后的请求核对召回范围。来源撤回或权限变化须按 App 策略排除相关记录，再走正常答复路径。[记忆快照](/manual/memory-and-learning) · [可运行的请求恢复案例](/manual/examples/resilience/)

## 观测

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 能定位失败阶段、工具或检索器 | 一条失败日志 | 补字段 |
| 能区分成功、降级、失败与取消 | 四类样本各一条 | 统一结果分类 |
| 日志不含密钥、完整提示词与未脱敏资料 | 抽查日志 | 脱敏或删除字段 |
| 降级与失败有独立统计 | 指标或报表 | 增加计数，而不是只看成功率 |

## 发布与回滚

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 发布包含资料、配置与索引的一致版本 | 版本号与构建记录 | 固定版本，不混用 |
| 回滚路径明确且演练过 | 一次回滚步骤 | 补回滚说明与旧版本保留 |
| 新版本不会读取旧版本的不兼容索引 | 启动自检 | 校验 identity 与 indexRevision |
| 变更原因与观察结果有记录 | 变更记录 | 补记录后再发布 |

## 回归

用[稳健性检查](/manual/workflow-development#检查-agent-稳健性)找出最可能中断交付的路径，再用[Agent 分层测试](/manual/workflow-development#test-agent-features-nodes-and-tools)把关键结果、节点路由和工具授权固化为可重复执行的用例。

| 检查项 | 需要的证据 | 不通过时 |
| --- | --- | --- |
| 关键协议与工具选择有离线用例 | 测试结果 | 用 MockGPT 补用例 |
| 失败、取消与预算超限有覆盖 | 测试结果 | 补边界用例 |
| 真实模型效果另行验证 | 人工或在线评测记录 | 不用离线用例替代语义验收 |

## 结论怎么写

发布结论应包含：本次版本、覆盖的样本、观察到的结果、未验证的部分和剩余风险。不要把“没有发现问题”写成“没有风险”，也不要把离线用例通过写成“语义效果已验证”。
