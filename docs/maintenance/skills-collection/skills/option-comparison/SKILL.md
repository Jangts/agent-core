# 选项对比

## 输入与接入

输入包含可辨认的选项、比较目标和约束。App 的 `read` 提供当前资料，可用 `discover` 定位对象、`query` 执行比较所需计算、`check` 补充业务规则。已有材料足以确定选项时不重复查询。

## 流程

1. 确认比较对象及决策重点，利用相关历史理解“这几个”等指代；会影响选项身份的歧义先澄清。
2. 根据目标选少量有意义的维度，区分必须满足的条件与偏好。评分和权重由调用方或明确目标决定，不自行假设。
3. 读取每个选项的实际资料，保留时间、适用范围和定位。搜索摘要、品牌印象和历史个案不替代当前依据。
4. 对齐单位、观察期间、功能定义和其他必要口径。不可直接比较的项目分别标出，不把空值当作劣势或不符合。
5. 按维度输出已确认差异与缺项。确定数量和成本比较使用程序结果；没有支持计算时不宣称完成精确测算。
6. 仅在证据足够、约束和偏好清楚时给有条件的建议，并说明其依赖条件。否则给可确认差异和下一步核实项，不强行排名。
7. 先交付关键结论，再按任务需要展开对照与出处；大集合先使用真实汇总，不能从有限明细估计全量。

## 结果与完成条件

结果包含比较维度、同口径差异、出处、未确认项与条件建议。完成指已覆盖明确比较任务；资料差异和用户偏好不足时允许不推荐唯一选项。

## 边界

不固定业务产品、价格来源、评分标准或准入规则。建议不自动授权购买、提交或修改配置；最终选择与实际执行按 App 合同处理。

## 验收场景

- 两个选项费用覆盖期间不同：先对齐或说明不可比，不直接判定便宜。
- 一个选项缺少当前资料：标明未知，不把缺失当作没有该能力。
- 用户仅要差异：交付差异，不追加无依据的排名或行动。
