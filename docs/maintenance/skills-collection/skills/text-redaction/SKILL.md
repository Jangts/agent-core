# 文本脱敏

## 输入与接入

输入是纯文本、使用场景和需遮盖的内容。规则可以指定字面量、原文中的区间、替换方式或需要识别的类别。可选 `detect` 在 App 允许处理原文的范围内识别指定类别，返回原文区间、类别及不确定项。已知字面量与区间可直接用确定性规则处理。

## 流程

1. 明确哪些类别必须遮盖、哪些信息为读懂材料需要保留。若收到文件，先由 App 提供获准处理的正文，记录本次覆盖的部分。原文只交给能处理该类内容的端口。
2. 在同一份原文上定位全部命中，检查边界和位置单位。Node.js 字符串索引以 UTF-16 代码单元计，适配器须转换其他索引单位并确保替换边界完整。含糊、越界或与原文不符的位置留待复核。
3. 合并重叠区间，覆盖完整敏感片段。区分不同对象有助阅读时，按本次材料与已知身份依据使用一致代称。同名且身份未明时保留歧义，不拼接出新的身份关联。
4. 生成新副本后，检查已知字面量及规则能确定的残留。匹配计数、实际替换区间数和待审项可分别列出，处理说明只引用安全位置与类别。必需类别缺少检测依据时，结果状态标明需要复核。

## 结果与完成条件

返回脱敏文本、已检查类别和范围、替换区间数及待审位置。必需检查已完成且没有已知残留时可报告“已按指定规则处理”。对检查缺失的输入，清楚标出副本的适用范围。

## 边界

结论仅覆盖给定规则和实际处理的纯文本。文件附件、隐藏属性、公开分享和原件修改各有独立的处理入口。

## 验收场景

- 同一编号出现两次，一处与更长的敏感区间重叠。两处均完整遮盖，处理说明没有回显原值。
- 一段包含表情的文字由外部检测器返回位置。核对位置单位和原文切片，避免错盖相邻字符。
- 用户要求遮盖全部姓名，当前只给出两个明确姓名且没有相应识别能力。可交付已遮盖已知姓名的待审副本，并点明其余姓名仍需检查。
