# 变更核对

## 输入与接入

输入是明确对应的基准状态、目标状态与检查目的。App 用 `read` 提供完整或明确范围的状态，可用 `compare` 执行确定性差异计算、`check` 应用特定规则。对象修订号只是比较依据，不要求 Skill 绑定 SDK 或平台版本。

## 流程

1. 确认两份材料是否属于同一对象、相同适用范围和可比较期间。上传更晚不自动表示更有效；不同对象的选型比较使用选项对比。
2. 读取所需正文或实际草稿快照。未保存修改以其真实快照为依据，不能用数据库当前值替代；搜索未命中也不能证明字段已删除。
3. 采用调用方提供的身份键和顺序语义对齐记录。区分新增、移除、字段修改与重排，不能把列表位置改变都当成对象替换。
4. 可由程序确定的差异交给 `compare` 或现有差异能力，模型负责解释。有限明细与完整计数分开；跨页状态不一致时保留限制。
5. 每个重要差异保留前值、后值、位置和比较范围。文字变化、语义变化、适用范围不同及无法确认分别表达。
6. 影响分析仅使用实际事实和明确规则。只请求比较时不扫描其他数据；需要排查关联影响时，按额外授权范围读取。
7. 给出重要差异、阻塞问题和需核实项，不把发现变化当成已发布、已保存或已应用。

## 结果与完成条件

交付差异摘要、可定位明细、比较范围和有条件的影响判断。完整性只覆盖实际比较过的对象与字段；没有基准时只能做单份分析。

## 边界

方法不固定数据模型、变更档位或发布规则，不写回、不自动迁移或修复。App 负责真实身份、并发和读取权限。

## 验收场景

- 同一组记录仅重排：报告顺序变化，不误报全部新增和移除。
- 仅有新材料，没有旧材料：做单份分析并列基准缺口，不编造旧值。
- 用户只指定一个字段：核对该字段，结论不声称覆盖全部字段。
