# 任务拆解与规划

## 输入与接入

最低输入是目标和期望交付物。已有要求、限制、原计划和实际进度可直接附上。只给资料引用时，可选的 `read` 按引用返回当前正文及出处。步骤编排、依赖检查和覆盖核对由 Skill 负责。

## 流程

1. 提取决定交付是否合格的要求，分别记录已确定的约束、可调整的偏好、影响开工的未知条件。短任务可以只安排一步。
2. 从交付物倒推必要步骤。每步写出要产生的结果，以及能够判断该步完成的观察或检查。标出依赖的具体产物，例如“用审定的名单排席位”。仅有先后偏好时保留为建议顺序。
3. 给步骤分配在这份计划内稳定的标识。检查依赖是否指向存在的步骤、是否出现自引用或环路，再从依赖已满足的步骤列出可以先做的工作。外部材料未到时写出解除阻塞的条件。
4. 修订计划时读当前版本，将新要求对照已有交付物，只调整受影响的步骤及其后续依赖。已完成状态来自实际进度。新增职责、日期和工时保留为建议或待定。

## 结果与完成条件

交付步骤表、当前可开始的步骤和阻塞条件。每项明确要求都指向至少一个可检查的交付物，未覆盖的要求单列。互相矛盾的硬约束须指出冲突位置和仍可推进的部分。

## 边界

输出是供采用或修改的计划。创建工单、分派人员、写入日历属于 App 的后续操作。

## 验收场景

- 要求“准备可打印的议程和报名表”。两份产物可并行准备，打印议程依赖定稿，报名表的完成条件单独列出。
- 原计划中设计已验收，新要求只改变交付格式。保留设计完成记录，调整导出和验收步骤。
- 用户指定 A 必须等 B、B 又必须等 A。指出环路和需决定的依赖，给出其余可先做的步骤。
