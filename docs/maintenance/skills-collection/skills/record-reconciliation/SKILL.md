# 跨来源记录匹配

## 输入与接入

输入为待核对记录、参照来源和匹配口径。App 声明标识的命名范围、能证明同一对象的键，以及允许一对一还是多对一。直接提供两个集合时，可按声明的键在内存建立索引。参照集合较大时，可选 `findCandidates` 根据批次返回授权范围内的候选、匹配字段和查询覆盖情况。

## 流程

1. 为两侧记录保留各自的来源标识和原值。只按给定规则规范化匹配字段，例如允许去除两端空白。前导零、大小写、地区和年份的意义由字段口径决定。
2. 优先按受信标识和明确的对应表匹配。名称、近似程度和别名可用来找候选。确认匹配还需满足身份规则和唯一性要求。没有确定键时可交付候选及需要补证的字段。
3. 结合本次所有输入检查冲突。在一对一任务中，两行都指向同一参照记录时，将冲突涉及的行一起列出。缺少参照侧唯一性依据时保留待核实状态。
4. 对歧义给出能区分候选的最少信息。按查询口径查完仍无候选可记为未找到。超时、分页未完或匹配字段缺失分别标注，保留原记录。

## 结果与完成条件

对应表每个输入行都有一个处置结果、可定位的参照标识或候选、依据和待核实项。汇总按输入行计数，保持与输入总数相符。下游可以取已确认的对应关系继续做差异核对。

## 边界

交付物是对应表。合并记录、改主键、删除重复行和导入落库由使用方另行处理。

## 验收场景

- 两份目录都出现“青禾”，参照库中有两个同名对象。列出二者及区分字段，保留歧义。
- 两行使用同一外部编码且规则要求一对一。两行均进入冲突组，处理先后顺序不影响结果。
- 参照服务只返回了首页且未命中。该行标为查询未完，不能据此建议新建对象。
