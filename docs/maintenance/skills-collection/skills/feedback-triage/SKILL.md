# 用户反馈归类

## 输入与接入

输入可以是一条留言或一批带来源标识的反馈。App 可直接给出分类表及现有事项。没有分类表时，按用户描述的现象、希望达成的结果和提出的办法整理。可选 `findRelated` 检索相似旧事项，返回可引用的标识、摘要和适用范围。

## 流程

1. 对每条输入找出可以独立回应的诉求，保留它们与原始位置的关系。一句话同时提出两件事时分别登记，涉及个人信息的摘录按 App 的可见范围裁剪。
2. 分开记录实际遭遇、用户明确表达的期望、用户建议的实现方式和整理者的推断。例如“总要重新填写”只证明重复输入的困扰，是否要自动保存仍待确认。
3. 按已给出的类别和受影响场景归类。无法确定类别的条目列出缺什么证据。相似旧项核对对象、条件和期望结果，重复报告保留各自出处，相反诉求并列。
4. 输出每组的条目数、不同来源数和可核实的影响。如果材料只能区分消息，就只统计消息。只有用户陈述或现有规则能支持紧急程度时才给出相应理由。

## 结果与完成条件

每项可处理反馈均有来源、现象或期望、分组和下一步建议。归并后的条目能追溯到原话，未归类、相反和信息不足的意见均可找到。重复频次与覆盖人群分别说明。

## 边界

结果供分流和后续澄清。创建工单、承诺排期和发布知识由 App 的相应操作决定。

## 验收场景

- 一人转述同一问题三次。保留三条出处，有身份依据时统计为一位反馈者。
- “导出太慢，还希望能换标题”拆成两个条目，当前速度和原因都需另行验证。
- 两条反馈分别希望默认展开和默认折叠。保留两种使用场景，共同标记为产品选择。
