# 文稿编写

## 输入与接入

输入是写作目标、可使用的事实与材料，以及已有格式或表达要求。可直接处理本轮提供的内容；外部引用通过 `read` 读取，可选 `check` 提供业务或表达检查。`generateArtifact` 仅在实际绑定且当前任务需要文件时提供附件生成。

## 流程

1. 根据现有信息确定文稿用途、读者、期望读者作出的判断或行动。缺少信息但不影响初稿时给出明确假设，不强制完整访谈。
2. 读取已有正文和必要材料。修订任务以当前稿件和明确要求为准，保留有效结构与事实，不恢复已经删除的内容。
3. 用最少层次组织直接结论、必要说明、依据和行动。仅要提纲时交付提纲，不擅自扩写成长文。
4. 形成正文，使用材料能支持的事实和数字；未知保持待核实或省略。示例与占位内容不得伪装成真实记录。
5. 从目标读者角度检查：是否能理解对象、前提、限制和下一步；关键术语有无歧义；说明是否只对写作者自身成立。不强制启动其他 Agent。
6. 按实际问题局部修订，再用已登记检查或交付复核核对相关事实。写作、事实查证与排版分别说明完成范围。
7. 默认交付正文；需要文件且生成成功时再交付实际引用。没有保存、发布或发送回执，不声称已执行这些动作。

## 结果与完成条件

交付可直接阅读的正文或指定修改、重要依据和仍需核实的事项。文稿符合当前用途与读者要求，事实没有因润色改变确定性；初稿生成不等于已获业务批准。

## 边界

不固定模板语言、品牌风格或具体文档平台。App 可以提供模板和表达规则；方法不内置个人偏好，不自动发布、收集长期资料或制作视觉稿。

## 验收场景

- 只要求调整两段说明：保留其他结构，交付局部修改。
- 提供事实不足以支持收益承诺：改为有条件表述，不发明数字填满方案。
- 用户要正文且没有文件端口：完成可用正文，不虚构附件链接。
