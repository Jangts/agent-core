# 数据质量检查

## 输入与接入

输入为数据范围和本次检查规则。App 通过 `scan` 读取有覆盖信息的数据，通过 `check` 执行实际登记的规则；`describe` 可提供字段解释。规则包含适用条件、错误含义和实现入口，不由模型临时推定业务必填项。

## 流程

1. 确定要检查的对象、字段、时间或修订范围及规则。不存在规则时先列可检查项和所需选择，不把通用模板当成业务要求。
2. 读取字段和扫描能力，采用稳定标识与可恢复游标；记录一致性是快照还是尽力读取。空页与总数变化按真实端口合同解释。
3. 在限定范围内逐批扫描，由程序执行缺失、格式、重复或跨字段检查。需要外部校验的规则必须有相应能力，不能从字段有值推断远端资源可用。
4. 由程序记录已检查数量、规则命中数量与受影响对象数量，避免一对象多规则命中被重复计为多个对象。有限明细独立说明截断情况。
5. 缺失值按实际规则解释：未知、空白和有效零值不混用；字段为空不自动证明业务错误，例外和不适用项分别记录。
6. 未覆盖全范围时交付实际覆盖与继续位置；数据在扫描期间变化时说明不能证明一致全量结果。反复游标或限制耗尽时停止并保留进度。
7. 给出优先处理的问题和证据；提出修复建议不执行修复，不让模型估算缺失的统计。

## 结果与完成条件

交付规则、扫描范围、精确计数、有限示例、一致性和未检查部分。只有真实扫描覆盖及规则检查均满足任务，才能称指定范围检查完成。

## 边界

不内置商品、客户或业务字段，不自动创建缺省规则、修改数据或删除疑似重复项。来源授权和有副作用的外部探测由 App 明确控制。

## 验收场景

- 一个对象同时缺两个字段：对象数为一，两个规则分别命中。
- 一千条中只检查了一百条：报告已查范围，不将命中比例外推为总量。
- 图片地址非空但未访问：只能说明有地址，不能报告文件可用。
