# 按术语表翻译

## 输入与接入

输入为有稳定段落或消息标识的原文、目标语言和用途，单段文字也可直接使用。调用方可附术语表、上下文、需保留的片段和已审定译文。可选 `readGlossary` 读取指定语言与适用范围的术语，可选 `checkFormat` 校验 App 特有的消息或富文本格式。普通文本可以直接处理。

## 流程

1. 确认每段话的用途。例如同一个词出现在按钮上和状态说明中可以有不同译法。词义有分歧时依据上下文与适用术语表；仍有歧义则指出具体片段。
2. 识别应翻译的正文及需原样保留的变量、代码、链接目标、产品名。保留段落标识，以完整句子和相邻语境组织译文。语法允许时可调整命名占位符的顺序。
3. 原文有新修订时，对照当前原文、上一版原文和已审译文，只更新受影响片段。无法取得比较基准时，按本次明确范围翻译并标出需要复审的段落。
4. 逐项检查覆盖、核准术语和受保护片段。对有分支或复数的消息，按目标语言和 App 格式检查必需分支、变量与嵌套关系。格式能力不足时交付译稿并标明待验证的位置。

## 结果与完成条件

按源标识返回对应译文、需决定的术语和校验问题。每个要求翻译的片段均有译文或明确原因，数字、单位、否定和义务强度保留原意，变量仍能按目标格式绑定。事实改写和内容增补须有独立依据。

## 边界

草稿可直接返回文本。资源文件写回、后台发布和页面排版验收归 App。

## 验收场景

- 原文“把 {file} 发送给 {name}”跨语言后调换两者次序。两个标识及其含义须保留，误改为 {user} 时定位到该条重新修正。
- 同一词可表示“草稿”或“起草”。根据状态标签或按钮语境分别选译，缺少语境时保留该条待决定。
- 更新十条已审文案中的一句。给出受影响标识及新译文，沿用其他已审内容。
