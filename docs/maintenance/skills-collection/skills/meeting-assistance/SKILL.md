# 会议整理

## 输入与接入

输入为会面目标和已有资料，或实际提供的会后记录。会前与会后可分别使用，不要求两个阶段同时完成。可用 `read` 补充相关材料、`check` 运行登记检查、`generateArtifact` 生成当前任务需要的文件；没有外部依赖也可处理本轮文字。

## 会前流程

1. 确定本次希望解决的问题、已知参会对象与限制，利用现有材料，不重复索要已有答案。
2. 读取相关的当前资料，整理已知现状、待决策事项和会影响讨论的未知；缺失时间或参会者不自动补造。
3. 根据目标给出少量议题、关键问题和必要预读，不强制填写无关背景。事实保留出处，内部提醒与可对外材料分开。

## 会后流程

1. 使用实际收到的记录或转写文字，不声称参加过会议、听过未提供的录音或自动读取了日历。
2. 分开记录已确认事实、自述或意向、明确决定、约定行动与待核实事项；消息时间不能冒充事件发生时间。
3. 行动项记录实际提到的责任人、截止时间、依赖和完成标准。没有明确内容的字段保持未定；“争取明天”不能变成已承诺明天完成。
4. 与已有记录冲突时保留依据，按当前任务局部修订，不因写纪要自动改变长期任务状态。

## 结果与完成条件

会前交付简短背景、议题和关键问题；会后交付分类纪要、行动项和未知。事实、意向、决定和完成状态没有混淆，内容范围与实际记录一致。

## 边界

行动项不是提醒、任务创建或发送授权。本方法只整理；保存、创建日程、通知他人或更新长期记录由 App 的独立能力按真实授权执行。

## 验收场景

- 记录中说“可以考虑，下周再定”：保留为意向与待决定项，不生成已确认任务。
- 用户只要会前五分钟提纲：按目标精简，不要求先填写完整参会资料。
- 只有转写文字且没有日历端口：整理纪要，不声称确认了日程或发送了材料。
