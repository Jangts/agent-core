# 操作指引

## 输入与接入

输入为用户要完成的操作目标和已有页面或应用状态。App 用 `readGuide` 提供说明，可用 `discover` 查找相关章节、`readContext` 读取当前状态、`prepare` 准备允许的引导入口。不绑定浏览器、前端框架、路由或控件库。

## 流程

1. 理解用户要知道怎么做、开始分步引导，还是直接执行。仅问功能或步骤不自动变成页面操作授权。
2. 已有说明先读相关章节；概览未提到某功能时检索完整指南，不能仅凭省略判定功能不存在。
3. 需要结合当前状态时读取真实状态，核对账号可用能力、前置步骤和未保存修改。历史页面位置仅作线索，不冒充当前页面。
4. 给出达到目标所需的最少步骤，采用应用真实名称和条件。未满足前置条件时解释用户可处理的下一步，不虚构控件或路径。
5. 用户需要引导且已绑定能力时，按 App 的允许清单准备入口或步骤。授权是否需要确认由 App 当前策略决定，不另加固定确认流程。
6. 跨页面或依赖前一步的动作保持真实顺序，取得前一步实际结果后再继续；不能因命令已经准备就声称页面已打开。
7. 没有可执行引导能力时交付准确文字步骤。遇到状态变化、取消或无权限时停止相关操作，保留可用说明。

## 结果与完成条件

交付可理解的步骤、必要前提或已经准备好的真实入口。说明完成、引导已准备、动作执行完成使用不同表述；最后一种必须有真实执行回执。

## 边界

方法不扫描屏幕或自行启用 UI 自动化，不自动切页、丢弃修改或提交表单。真实交互由 App 端口及当前用户授权决定。

## 验收场景

- 概览没有字段说明，但指南章节有：读到正文后解释，不能声称无此功能。
- 已生成跳转入口但未执行：只报告入口已准备，不报告跳转成功。
- 当前有未保存修改：保留修改，按 App 策略处理后续导航，不擅自丢弃。
