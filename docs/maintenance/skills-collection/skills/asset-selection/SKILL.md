# 已有素材选用

## 输入与接入

输入是使用场景、选择数量、硬性条件及偏好。已排除或已使用的素材以真实标识传入。`discover` 返回允许选择的素材标识、可用引用和已知元数据，调用方直接给出候选清单时可在内存完成这一步。可选 `inspect` 按标识读取对应内容或预览，并标明实际读取的范围。

## 流程

1. 将主题、用途和要求转成选材条件。分清必须满足的约束和可取舍的偏好，例如横幅尺寸属于硬约束，偏爱暖色可以作为排序依据。
2. 在给定范围查找候选，保留来源标识和具体变体。同一作品的主图、不同裁切和细节图要能分别定位。用明确排除的标识筛选候选。
3. 尺寸、格式可由已核实元数据判断。颜色、主体位置、背景干扰等内容要求需要与该变体对应的预览或可靠标注，同时说明判断依据。文件名和链接只能帮助定位。缺少内容依据的候选列为待看。
4. 从满足硬约束的候选中按用途选择，给出匹配理由及必要取舍。返回引用须与核对过的素材和变体一致。限定范围内没有合适素材时列出缺口，方便用户决定是否放宽条件。

## 结果与完成条件

交付可引用的选中项、依据和未核实条件，或给出范围清楚的空结果。展示候选、用户选定、已经使用是三个分别可记录的事实。

## 边界

本方法选择已有资源。生成新素材、改图、投放以及写入“已使用”记录交由 App 处理。

## 验收场景

- 同一素材有方图和横图，用户指定横图。核对并返回实际横图的引用。
- 文件名写着“留白”，用户要求右侧可放标题，库中没有位置标注且预览不可读。保留为待看候选，说明尚未核实右侧构图。
- 用户排除了刚才的第二张。根据上次展示清单解析其标识，新选择排除该项，同时保留其他候选的使用状态。
