# 资料综合

## 输入与接入

输入为整理目标、实际材料或允许发现的来源范围，以及读者与篇幅偏好。App 的 `read` 提供正文及覆盖信息，可用 `discover` 查找额外来源、`check` 检查结果。单份材料摘要与多来源研究使用同一方法，按任务选择所需步骤。

## 流程

1. 判断交付是快速摘要、指定主题综述还是较完整的研究简报。已有目标足够时直接工作，不强制逐项询问模板信息。
2. 列出任务相关来源并实际阅读。若任务允许扩展查询，再做目标明确的发现；目录与摘要仅用于选源，不能当作已读正文。
3. 长材料按自然章节与真实读取范围整理局部要点，保留出处、例外、冲突和未覆盖部分。局部摘要不能把未知补齐成完整结论。
4. 围绕主题和问题综合，不仅按来源依次复述。相同来源的转载不当作多份独立证据；不明确的转引标注其来源关系。
5. 对关键论断核对原文，区分事实、作者观点、归纳与建议。来源日期与适用范围不同的判断保留差异，不用多数表述消除冲突。
6. 根据读者和篇幅压缩重复表达，保留会改变结论的条件、反例和缺项。要求全文覆盖时检查实际覆盖，不凭摘要自评完整。
7. 交付摘要或简报、关键依据与局限。受限无法完成时保留已完成主题和具体缺口，不自动扩大研究或反复搜索。

## 结果与完成条件

结果包括直接结论、主题要点、可定位来源、矛盾和未覆盖部分。重要判断能追溯到实际材料，覆盖声明与读取证据一致；主题摘要不宣称穷尽全部相关研究。

## 边界

方法不绑定网站、知识库或笔记平台。联网、文献获取、创建页面和发布由实际 App 端口分别提供，不因要求研究而自动取得这些能力。

## 验收场景

- 三份材料部分重复：按主题归并，保留独立来源和条件，不重复堆砌。
- 长文只读到前半部分：可交付部分摘要，不能称全文总结。
- 只有内部资料而无搜索端口：据现有材料综合，不声称完成互联网调研。
