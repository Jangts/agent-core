# 任务交接

## 输入与接入

输入为可辨认任务、交接目标及接收者需要知道的范围。App 的 `read` 提供当前事实，可用 `discover` 定位任务、`readHistory` 查看相关记录、`check` 检查交付、`generateArtifact` 生成需要的文件。仅整理一次会议时使用会议整理。

## 流程

1. 确认任务对象与交接目的；存在会混淆对象的指代时澄清。接收者身份影响表达与必要字段，不增加共享权限。
2. 读取当前记录、相关材料和实际修订信息；历史摘要只作线索，不覆盖当前人工修订或恢复已删除内容。
3. 组织目标、当前进展、已经发生的结果、关键依据、等待对象、未决事项和下一步。完成一个阶段不表示整个任务已结束。
4. 需要历史解释时按对象和期间读取真实记录；时间线缺口保持未知，记录先后不能独立证明因果或责任。
5. 下一步注明已知责任人、依赖、期限与完成条件。建议与已约定任务分开，缺少责任人或日期时不擅自补造。
6. 检查材料引用是否实际可读、覆盖是否充分，移除接收者不需要的敏感内容；临时可访问链接不描述为永久档案。
7. 优先交付接手者能据此行动的摘要，再按需要展开来源与未决义务。生成交接文件不等于共享、发出或完成交接手续。

## 结果与完成条件

交付当前概况、已落实结果、依据、未决义务与接手动作。结果反映实际读取范围，未决事项没有被收尾措辞掩盖，接手者能辨认已发生与建议继续做的事。

## 边界

不绑定业务建档模型或生命周期，不自动结项、改负责人、转移所有权、创建提醒或发送消息。真实操作另按 App 合同与当前授权执行。

## 验收场景

- 主要成果已交付但仍有未决义务：保留待办，不宣布任务全部完成。
- 旧摘要与当前人工记录冲突：使用当前记录，标出所需核实，不恢复旧内容。
- 要求交接说明但未要求共享：交付正文，不自动向接收者发送。
