# 通用 SKILLs 收集与整理草案

本目录保留 20 项方法的收集草稿、来源与接入设计。优先级表示建议实施顺序。[通用任务 SKILLs](../../../packages/agent-core/development/docs/api/skills.md)列出随包交付的方法，应用可通过任务角色、业务方法或对比场景选用。导入预检源自 WFJ Console 的分类目录和 Campaign 预览与确认流程。

资料综合、修改草稿、反馈归类、术语翻译和文本脱敏仍为候选。

## 分类与收录边界

面向使用者的分类采用 **Core & Support、Tool Kit、SKILLs**。Core 与 Support 仍保留执行契约和推荐实现的职责区别；Tool Kit 汇总可组合的可选能力库；SKILLs 提供面向任务的通用方法及可接入流程。Tool Kit 这一总称与现有 `/kits/tools` 子模块不是同一范围。

SKILLs 由 App 选用，可以引用 Core、Support 和 Kit；Core 不按具体 Skill 名称分发。模型根据用途与输入选择已启用的方法，程序继续校验参数、授权和结果。Skill 的名称、说明与方法正文都不授予权限。

收录标准：

- 能说明完整任务、必要输入、结果和结束条件，值得在不同 App 重复使用。
- 去除应用工具名、产品字段、路由、角色、地区政策和品牌表达后，流程仍然成立。
- 默认方法能减少 App 的编排工作，App 主要绑定数据、规则、权限与实际操作。
- 读取范围、事实依据、计算口径、未知和失败去向明确；模型自评不替代真实校验。
- 需要程序时只接受 Node.js；Skill 不固定 Node 主版本、框架版本、供应商 API 版本或外部 CLI。最低运行要求统一服从包声明，外部系统通过 App handler 适配。
- 外部资料用于提炼方法，本文档与流程草稿独立撰写，不导入第三方脚本、安装命令或平台授权流程。

路由选择、通用重试、JSON 解析、分页、缓存等机制继续由 Core、Support 或 Kit 拥有，不单独包装成面向用户任务的 Skill。

## 方法之间的边界

- 取证问答解决明确问题；资料综合组织多个主题，不以回答一个问题冒充读完全部材料。
- 结构化提取保留原始事实与字段；表格分析执行明确的计算，不让模型凭样例行统计全量。
- 选项对比比较不同对象；变更核对比较同一对象的两个状态。业务资料的修订标识可作为输入事实，不把它与 SDK 版本耦合混为一谈。
- 数据质量检查检查来源数据的已登记规则；交付复核检查成稿、结论与附件如何使用这些数据。
- 操作指引解释如何操作；修改草稿准备指定变更。二者均以真实 App 回执区分已准备和已执行。
- 会议整理覆盖一次会面；任务交接覆盖一个持续任务的当前事实和未决义务。
- 文稿编写负责形成正文；文件解析、排版、保存、发布和发送各自通过实际端口执行。
- 单个目标需要拆步骤时用任务规划。多件现有事项要决定先做哪件时用待办盘点。要告诉接手者当前做到哪里时用任务交接。
- 两个来源还无法逐行对应时先做记录匹配。已有可靠对应关系后，可以直接做变更核对或数据质量检查。
- 文稿由已有材料形成新正文。翻译以源文为准，按片段保留术语、变量和事实。
- 读者需要综述时用资料综合。需要决定每条意见如何处理时用反馈归类，原话与诉求之间保留可追溯的对应关系。

## 暂不独立收录

| 候选 | 处理依据 |
| --- | --- |
| 通用 PDF、Word、Excel 转换 | 属于文件适配与生成能力。收集到的部分实现依赖 Python、外部二进制或特定工具链，不直接迁入；以后有独立 Node.js 实现和真实合同再评估 |
| 提醒、定时跟进、自动发送 | 必须依赖 App 的真实调度与发送端口；会议和交接中的行动建议不能自动获得这些权限 |
| 自动学习并发布 Skill | 提炼经验、修改程序和发布能力是不同操作，首批不把反馈或文字草稿直接转成已启用能力 |
| 自主多 Agent 团队 | 委派与并行属于执行组织方式；先复用现有能力，不把所有任务都改成多 Agent |
| 按运行记录回答复盘问题 | Cafe 与 Banker 已通过 Reflection Kit 读取授权元数据，交付有证据的观察、待验证假设与建议。此请求可沿用现有入口，见 [Reflection Kit](../../../packages/agent-core/src/kits/reflection.ts) |
| 银行准入、商品发布、特定平台埋点 | 保留在业务 App；可借鉴通用 Skill 的流程，不进入公共 Skill 的默认规则 |

## 从草稿到可接入流程

1. 按 [接入设计](contract-proposal.md)为 P0 做最小实现样例，确认默认行为与 App 必填依赖。
2. 在现有 Core 合同下实现 Node.js 流程；静态清单引用具名实现，装配时校验 handler 与输入输出引用有效。
3. 用每份方法里的正常、缺项和边界场景建立最小回归。取消、账户隔离、权限与副作用按真实接入补充必要用例。
4. 分别验证 App 显式调用与可选模型发现；未绑定必需依赖的 Skill 不出现在可执行能力目录中。
5. 实现稳定后再确定公开路径和发布内容，同步中英文使用文档、示例、开发 Skill 与文档站来源。公开资料仅保留通用内容；业务来源映射留在维护资料。

本文与方法中的验收场景均为设计材料，不表示已经运行、真实模型验证或应用验收通过。
