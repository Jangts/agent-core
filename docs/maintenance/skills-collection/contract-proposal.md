# SKILLs 的 Node.js 接入设计草案

本文描述待实现的接入方向，不定义当前 SDK 可调用 API。现有合同仍以源码及使用手册为准。

## 程序与方法分工

方法说明负责用途、步骤、证据要求和完成标准。Node.js 实现负责可程序检查的输入、阶段、结果与结束条件。App 的 `handles` 提供业务访问与局部规则；模型、工具、取消和预算复用现有 Core 服务。

每个 Skill 只要求实际需要的 handler，不要求 App 实现统一的大接口，也不把每一步都变成回调。比如结构化提取提供默认提取与有限修复；App 不应为了接入再次编写整套提取提示词和循环。

| 所有者 | 负责内容 |
| --- | --- |
| Core & Support | 模型与工具调用、输入输出合同、预算、取消、状态和推荐接线 |
| Tool Kit | 可独立复用的检索、证据、检查、差异、查询、交付等机制 |
| SKILLs | 通用任务的默认编排、通用指令、结果检查、缺项与结束条件 |
| App | 身份、授权、来源、字段含义、单位、业务规则、真实存储及外部操作 |

## handler／handles 接入

`handles` 表示一组有类型、具有任务意义的命名接入点；不是从 Markdown 解析出来的函数名或任意脚本路径。使用普通函数、带原型方法的对象或实例均可，接收者按现有 Core 合同保留。跨请求复用定义，本次用户、信号与状态通过请求上下文传入。

下列代码仅展示候选接入形态；`createStructuredExtraction` 和其选项不是现有导出：

```ts
// 设计示意，尚未提供此创建函数。
const extraction = createStructuredExtraction({
  model: runner,
  outputSchema: app.recordSchema,
  handles: {
    read: app.sources.read.bind(app.sources),
    check: app.records.check.bind(app.records),
  },
});
```

上例显式绑定方法所属实例，保留真实接收者；也可传入普通函数或沿用已有保留宿主的注册机制。最终教程须使用实现后确定的公开入口，不能将这一示意作为现有 API 发布。

接入合同应满足：

- 输入在前，上下文在后；沿用 `OperationContext`、schema、检查结果及现有模型／工具调用合同，避免同义类型再造。
- 每个 handler 的输入输出、同步或异步属性、前置条件、副作用与错误去向均有类型和文档。I/O 可异步，既有同步解析不能静默放宽。
- 必需依赖在装配时校验；可选项缺失有真实可用的降级，不能静默跳过完成所必需的检查。
- 静态批量注册采用类型化清单与具名实现。Skill 说明、模型可见投影和实际可执行集合引用同一声明；声明目录不代替真实授权。
- 不要求将所有 handler 暴露成模型工具。App 注册的工具走 Core 工具合同；纯计算与固定步骤保持普通具名调用。
- 不增加通用 Skill 调度引擎。顺序处理可用普通调用链，分支与循环按需要复用现有 Workflow。

`catalog.json` 的 `requiredHandles`／`optionalHandles` 只是本次整理的依赖槽位，不是最终类型名称或允许运行任意函数的清单。必需槽位表示合并默认实现与 App 绑定后必须具备该能力，不表示每项都要求 App 重写；例如直接提供正文时，`read` 可以由默认内存实现满足。来源发现和读取可映射到既有 Knowledge、Retrieval 与 App 工具；同名接入点也不意味着所有 Skill 的参数类型相同。

## 需要闭合的最小合同

| 方面 | 设计要求 |
| --- | --- |
| 来源 | 返回真实引用、实际读取内容、定位、读取范围和来源状态；搜索命中与正文读取分开 |
| 模型 | 默认生成使用 App 提供的 Runner 或当前执行绑定，不固定 Provider、模型名、wire 格式和 SDK 版本 |
| 检查 | 结构检查使用已有 schema；事实和业务检查使用明确依据。schema 通过不等于事实被证明 |
| 结果 | 每个 Skill 有自己的类型化值、证据和未完成部分；共享真实共性，不强迫所有流程使用同一套阶段或状态字段 |
| 缺项 | 区分可继续的缺项、需用户补充的输入及不能继续的错误；不为每个任务制造额外资料要求 |
| 结束 | 默认有界，不因要求完整而无限查询／修复；耗尽时准确返回已完成范围 |
| 授权 | 每次真实读取、生成和修改由实际 handler／工具检查；描述、历史同意和 Skill 启用均不能替代当次权限 |
| 副作用 | 准备、生成、保存、提交、发送分别有真实回执；取消不假装回滚外部已发生的结果 |
| 观察 | 沿用 Core 事件及 Kit／App 的局部观察端口，不新增平行日志系统 |

## Node.js 与版本边界

- 随 Skill 提供的程序只使用 Node.js，源码可采用仓库既有 TypeScript 编译路径；不通过 Node 启动 Python、Shell 或其他解释器来规避限制。
- Skill 不内置针对包版本或框架版本的分支，不要求固定某个模型 SDK、桌面应用或 CLI 版本。受支持运行要求只在包级声明和相应端口合同中维护。
- 远程 API、数据库、浏览器与文件格式由 App 适配；相应产品的版本兼容逻辑留在适配方。Skill 只消费稳定输入输出。
- 文件系统、网络、进程和环境变量访问不是默认能力；需要访问时由 App 显式提供已授权端口。
- 文档修订、来源时间及对象并发标识是业务数据，比较状态和避免覆盖时仍可使用；它们不成为 Skill 自身的版本分发体系。
- 首批不提供脚本，避免以空壳 Node 脚本冒充已完成的流程。实现阶段对真实纯计算选择 Node 默认实现，对业务访问保留 App handler。

## 完成性核对

每个 Skill 的实现应能回答：App 最少要填什么；省略哪些配置仍可直接使用；哪些步骤可替换；绑定后怎样发现和调用；实际结果怎样证明任务完成。最小示例不应依赖未声明的业务上下文、隐藏全局状态或固定平台服务。

程序侧回归验证结构、顺序、覆盖、引用、取消和权限；真实模型评估另行检查选用方法、提取事实和答案质量。两类证据不互相替代，开发机测量不作为吞吐或容量结论。
