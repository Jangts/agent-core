# Core 与 Support 接口整改

## 原则

- Core 拥有接口与执行保证。最小启动用标量与普通对象。结构化合同允许 Support 产物、类实例和自定义对象直接接入，并保留实现所需的方法和身份。
- Core 运行路径独立于 Support。运行确实需要封存、生命周期或实例身份时，由 Core 提供构造器，Support 和外部实现可以继承。
- Support 提供首选实现。默认行为先满足真实解析、授权、预算、取消、记录与并发隔离，再通过缺省、复用和代指减少接线。
- 进阶沿用同一个 Core 合同。示例先用普通对象展示最小 Core，再用 Support 展示项目接入，最后只替换需要自定义的实现。
- 路由生成器与手写路由共享配置合同。专用默认值由生成器决定，Workflow 校验收到的配置。
- 本项目按全新版本同步发布 SDK 与 App，不承担历史格式兼容；旧类型、字段转换、持久记录升级和旧日志读取分支均移除。当前任务恢复、预算、取消、授权和期限保证继续有效，本次代码整改不操作运行数据。

## 逐模块验收补全规则

| 盘点项 | 需要核实的行为 |
| --- | --- |
| Core 缺省 | 说明每个可选字段省略后的行为，以及默认值如何满足执行边界 |
| Support 推荐策略 | 逐场景说明默认值、生成规则和 handler，允许多个构造或有类型的策略选择，展示如何覆写并沿用同一 Core 合同 |
| 字段推导 | 找出重复填写的 ID、引用和字段，从已经提交的配置推导并校验冲突 |
| 批量生成 | 从已有清单生成枚举、字典或数组，校验重复项和引用，避免并行维护两份配置 |
| 封装收益 | 用同一业务的前后示例展示省去了哪项决策、配置或实现。仅原样接收并返回同形对象的入口纳入删除或合并审查 |

文本传输作为对照项。Core 默认文本传输可以直接用；Support 文本传输为需要独立登记的场景提供完整的文本处理实现，调用者只需确定 ID 和必要的覆盖项。能力目录另查生成的模型投影与运行时注册是否共享同一份来源。

## 首轮源码盘点与实施顺序（已落实）

| 批次 | 覆盖面 | 整改前的检查点 | 验收 |
| --- | --- | --- | --- |
| 1 | 工具、schema、能力目录 | 工具运行实现依赖 Support 所有的声明类型。工具绑定时报告回调的接收者需要保留 | Core 拥有执行声明。普通对象与有状态实现按同一合同绑定，保留解析、授权、取消、结果和诊断 |
| 2 | ModelRunner、Provider、交互、传输、阶段 | 模型子入口同时转出 Core 与 Support。类型化传输目前要求已登记的同一引用 | 区分导出导航与运行依赖。确认实例身份约束的必要性，验证自定义实现和同源能力投影 |
| 3 | 上下文、压缩、选择 | Core 上下文入口转出 Support 装配函数。检查执行阶段实际依赖及 schema 归属 | 纯配置可以直接启动，Support 复用片段与预算策略，压缩与选择共用请求预算 |
| 4 | Engine、Workflow、日志、流、预览 | 应用节点仍有诊断转传，执行元数据与 App 诊断输出接线需要分离 | 同一业务接入日志只改装配，取消、回执和父子链正确。可替换输出端口 |
| 5 | Support 装配目录、聚合出口、Kit | Support 独立入口曾混入 Kit；公开导出、App 消费者及示例需要同步归位 | 每项标明合同所有者与默认实现。Kit 保有局部协议，旧入口同步移除 |

每批按公开符号参考对齐源码与文档，使用 Banker、小可乐或可运行示例验证真实调用。范围包括根入口、独立子路径、类型导出和双格式发布。日志与持久数据只核对当前结构，不提供历史格式兼容。

第一批已把工具执行声明归到 Core，并修复直接使用有状态工具实现时报告回调的接收者。后续批次的实现与证据记录如下。

本轮核对了 Core 的传输入口。Runner 注册时接收结构化 `ModelTransportDefinition`，普通对象和类实例都可登记。类型化句柄调用要求引用已经登记的同一对象，以保证返回类型对应真实解析器。同名外部对象可在装配阶段明确登记，调用时也可用 ID 代指。现有聚合入口的 Support 转出属于现行聚合导出，独立 `/model` 入口直接指向 Runner。

schema 快照现在由共同基础实现提供。Core 模型能力注册、Support schema 工厂和两个 Kit 共用同一规则。能力模块目录也保留传入模块实例，工具集合及归属在登记时快照。模块 ID、说明与登记定义应按只读合同维护。

兼容 Provider 的审计发现，原来的 `requestBody` 可以覆盖已配置的模型、输入和请求预算。Support 现在在发出 HTTP 请求前拒绝这些覆盖，静态配置在构造时校验，动态配置在使用时校验。Banker 和小可乐现用的供应商扩展仍可通过同一入口配置。对照测试覆盖静态与动态配置以及扩展字段透传。

Provider 的请求端口现在保留原实现的接收者。可直接传实现了端口合同的类实例，回归使用原型方法和私有状态验证。小可乐和 SDK 调用样例均使用命名配置，公开位置参数已移除。

上下文装配现已统一使用命名请求。两端将预算策略随各自的 builder 装配一次，每次构建只传输入。独立调用仍可以覆盖该次预算。Core 的上下文子入口直接导出原生片段组装机制，Support 继续提供上下文 builder。可运行统一示例和回归覆盖静态预算、带私有状态的动态预算与单次覆盖。

诊断入口收敛为 `createDiagnostics({ output, runId, spanId })`，Core 直接接受实现输出接口的对象，并绑定原接收者。Provider 观察关联采用 Support 的 `createProviderObservationScope`。Banker 与小可乐删除各自维护的子作用域映射，继续各自决定内容采集及写入。日志会话与文件格式仍由 App 所有。节点报告合同与剩余 App 模型调用接线尚待逐项迁移。

节点诊断补充统一为 `report(update)`，返回 `payload` 和 `subs`。Loop 按内容策略读取状态更新副本，并把信息挂到完成或跳转事件上。旧 Workflow `debugSteps` 回调和上下文别名 `round`、`runtime` 已移除。业务模型调用的诊断传递仍有应用消费，后续需随实际模型作用域迁移。

节点模型调用补齐了结构化传输句柄入口。Support 生成的传输与外部实现都可登记后按原引用调用，并从传输合同推断结果。离线 miniapp 使用 Support 生成的句柄，自定义传输回归使用私有状态验证接收者保持。小可乐的阶段目录改用现行的 `capabilityIds` 与 `transportId`。

Support 独立入口与根入口的 `Support` 现共用一份导出。独立入口原先混入的意图、范围、交互及工具生命周期能力归各自 Kit 子入口，应用的 `breakWhile` 导入继续有效。SDK 双格式构建和 336 项测试通过。

模型公开调用已收敛到 `invoke`。命名请求使用 `stageId` 和 `input`，`transport` 同时接受 ID 和已登记的原对象。SDK 类型测试覆盖输出推断。Banker 与小可乐按当前源码编译后，原生交互、上下文、预算和截止时间共 40 项应用测试通过。上下文内部的 `callModel` 已采用命名请求。Support 压缩与选择工厂沿用 `transport` 字段引用已登记传输，选择器可由内置解析合同补全指令。

Schema 入口的收益按来源核对。`fromJsonSchema` 从一份 Schema 生成验证器并统一同步错误合同，`fromParserSchema` 从已有解析库生成 JSON Schema 并保留原 parser 接收者，`defineSchema` 固定声明快照及解析方法。Core 接受同一个 `SchemaAdapter` 合同。旧的 `jsonSchema` 别名和位置转换参数已迁移，Banker 的 Office Schema 使用 `fromJsonSchema`。

工具声明工厂已收敛到 Core 的 `ToolDefinition`。Support 固定 Schema 和回调，检查授权结果，工具目录据同一声明生成模型能力与可执行目录。旧的名字字段、单独输入解析函数和布尔授权分支已移除。Banker 决策协议的模型字段仍由业务合同定义为 `name`，其枚举值改从已注册工具的 `id` 生成。

此表记录 Support 保留理由与证据。Core 构造、Workflow 配置、模型能力与传输、Kit 合同及真实消费者均已按本轮原则收敛；当前验证结果以 API 实施记录为准。

Workflow 原始配置与实例查询已统一命名。构造、扩展和 fork 共用现行节点合同，原始路由使用 `targetNodeId`。节点和路由的 ID 生成仍由各自的专用生成器负责，Workflow 仅处理已有标识的重复消歧及占位符展开。SDK 345 项测试及两端后端类型检查通过，诊断归一化只校验当前 v2。

## A 计划之后的策略化补全（原批次记录）

以下记录 A 收口时的后置范围；已完成的 B 及本次策略收口见下方当前实现，不再据此判断现行接口缺失。

用户补充的策略化能力当时安排后续单独实施。Support 可按场景提供快慢、质量、大小或预算档位，同时允许精确数值、自定义函数和完整配置覆盖。多种构造器或有类型的策略参数均可表达不同推荐实践。Core 继续接收基础合同。

候选包括上下文选择的速度与保留量偏好、上下文保留和压缩策略、Provider 的已知模型能力与交互策略，以及从已有清单生成预览字段和工具投影。先明确语义和映射依据，再确定档位参数。当前选择器的策略扩展草稿已撤回，现行 API 继续使用现有配置。

A 计划已完成列出的公开入口、Core 配置及事件别名、真实消费者和示例迁移。策略化推荐及过程事件统一继续作为后续设计。

过程事件统一另行设计：App 注册监听器，Core 在执行事实发生时调用；Core 不主动控制 App 展示，也不通过进度查询提供状态。固定流程与节点动态应复用统一的事件身份、载荷类型和订阅规则，日志持久化只是 App 的一种消费者。状态观察保持旁路，内容流交付保持等待消费的语义。当前已有节点生命周期观察与模型分片交付，尚缺上下文处理开始通知、节点内持续进度及统一的过程事件订阅面，不能将现状写作完整实现。

Workflow 新事件已去除身份与目标的重复字段，统一使用 `workflowId`、`nodeId`、`roundIndex`、`targetNodeId`。诊断读取只接受现行 v2，回归覆盖输入副本隔离和重复校验。应用事件消费者同步迁移。

模型输出额度字段已统一为 `maxOutputTokens`。兼容 Provider 的静态配置和单次选项按接口读取，支持 getter；静态配置形成快照，动态配置保持每次读取。直接 Provider 调用与动态配置均在 HTTP 之前校验输出额度，新增回归覆盖非法值及类配置。两端应用已有显式配置转换，继续各自维护业务配置名称。

ModelRunner 构造已移除位置参数、顶层 signal 和嵌套 config。预算字段按同一个顶层合同配置，execution 持有取消和诊断。类型回归拒绝旧 config，原有限额、Token 预留、错误元数据和子调用回归继续覆盖。ports 已移除，处理器通过 contextCompressors/contextSelectors 登记，观察、输出和错误回调使用 observe、sink、errors。

AgentCoreEngine 已统一配置对象、maxRounds、execution、errors 与 observe，Loop 和 Workflow 共用同一预算及执行配置。自编排通过 CoreStep/StepOutcome 的 run 入口保留，旧 undefined-as-continue 的 runUntil 已迁移。fork 继续继承预算与观察策略，父子分支日志身份由原合同管理。

错误诊断视图 `AgentErrorInfo` 统一使用 `stageId`，内部重抛注记同样只记录这一字段。回归验证冻结错误身份、HTTP 重试性及压缩子调用原始阶段保持。日志读取不再转换历史字段。

模型能力注册已移除 input/parse 旧声明和查询别名，ModelCapabilityRegistry 与 Support.defineModelCapabilities 共用 inputSchema/resolve 合同。原生和 JSON 交互适配器直接从 inputSchema.jsonSchema 生成请求，两端模型协议继续使用各自的业务解析器。

模型传输注册已收敛到 prepare/collector 合同，移除旧 decode/interaction 注册类型。Core 注册只固定原 prepare 接收者；具体解析由收集器完成。SDK 测试中的自定义传输通过该公开合同实现，原始输入解码、异步解析拒绝及类私有状态回归继续覆盖。

后续上下文归属调整纳入计划 B。装配、压缩和选择策略及可直接配置的 Workflow 节点由 Support 提供，Core 保留输入合同、包含传输指令与 Schema 的实际测量、最终预算校验、取消、超时和统一日志。节点按 App 配置的 Workflow 条件和路由调度。迁移前需明确测量接口、共享调用额度及准备阶段的日志关联；A 的接口迁移与追加补正验收单独记录。

节点是这一设计的执行接入方式。Support 的推荐算法和第三方自定义算法均实现相同的 Workflow 节点合同，Core 不限定压缩算法、分组、轮次或策略管线，也不通过专有上下文钩子执行这些步骤。App 将节点及触发条件配置进 Workflow，Core 按图调度；不能为了自动压缩而在 Core 内隐式插入 Support 步骤。压缩的进入、完成、失败、耗时和执行顺序纳入 Loop 的普通节点日志，节点通过已有 payload、subs 报告补充信息，不自行维护另一套日志。最终模型请求仍接受 Core 的通用输入预算校验，节点内部模型调用仍消耗同一次任务的调用预算并继承取消与超时。

意图与范围 Kit 的声明、登记结果和查询投影已使用同一组规范字段。两端消费者按实际字段检查，Microcola 的模型意图枚举改用 ids()，工具依赖校验读取 toolIds；业务 wire 中的 goal/scope/target 保留。批量 create 与分阶段构造均有实际装配用途，不再把前者标记弃用。Normalization、Candidates、Delivery 与 Projection 已移除旧配置或调用分支，保留已有候选边界、阶段交错、显式完成、取消检查和投影算法。

本组验证：SDK ESM/CJS 构建及 351 项全量回归通过；server 编译与 banker-api 类型检查通过；Microcola 意图、Workflow、页面上下文和查询边界 19 项回归通过；work-with-kit 离线示例可运行，公开符号参考已重新生成。该结果只覆盖当前源码与离线合同，不代表真实模型或 UI 验收。本组结果是阶段性证据，后续全量实施结果见现行 API 实施记录。

Interaction 的公开实现已收敛为 InteractionProtocol、CommandCatalog、Command 及对应声明，移除历史全称、缩写、旧工厂和字段别名。Microcola 与 Banker 的协议字段同步为 jsonSchema，断言调用使用 assert。自定义动态 keys、输入选择字段代指和 App 的 wire 格式继续有效；它们是实际协议扩展，与 SDK 旧 API 兼容分支分开处理。协议 envelope、字段 getter 与 handler 类实例保持原接收者，绑定不要求特定协议实例。

Interaction 组验证：SDK ESM/CJS 构建、355 项全量回归及两端编译通过；最后的绑定快照调整后，协议与公开类型 20 项定向回归通过。Microcola 的意图、聊天协议和原生能力 18 项，以及 Banker 的原生能力与交付完整性 15 项回归通过。源码与现行用法文档不再使用旧名称，迁移表及防残留测试保留旧拼写用于说明移除项。未调用真实模型、打开 UI 或部署。

## Support 策略收口（2026-11-05）

Core 仅提供基础且广泛的合同与执行保证；所有场景名、推荐算法、预算档位与供应商推理字段生成均由 Support 提供，不进入 Core ModelOptions 或调度分支。

| 原计划目标 | 当前实现与覆盖 |
| --- | --- |
| 完整 Core 上下文合同 | builder.plan/build 接受 additionalMessages、originalFragments、mutableFragmentIds；复用 Core 审计、装配和预算；类 getter 请求与独立 ContextPlan 实例均保留 |
| 自然场景上下文补全 | recent/continuity 与 compact/balanced/extended 可组合；字符比例和完整轮次数有公开映射，精确参数优先，不将字符比例称为语义保留率 |
| 选择与多步骤自由度 | 单策略和策略数组生成相同 policy/compressors/selectors；完整 selection、自定义处理器、steps替换和字符/token水位均可配置 |
| 模型与预算策略 | createModelStrategy 从声明模型和推理方案选择，生成完整 ModelRunnerOptions；small/medium/large 公开本地额度映射；精确设置、0、Infinity与Core字段保持有效 |

### 第二轮组合与边界复核

- 显式 `steps` 替换不再生成或要求已被替换的默认处理器；缺省选择只依据最终步骤。
- 上下文处理与 Core 使用相同字符预算域；结构化片段、附加消息和图片按合同读取后固定数据，原计划在异步期间的修改不影响本次预算。
- Provider 的配置函数、getter、推理 mapper 与请求扩展先形成同一次实际快照，再校验和使用；取消中止后续步骤，保留原始取消原因。
- 预览资格先快照再校验；默认路径仅来自真实 Schema 已声明的 text/bubbles 字段，避免校验与实际投影路径分离。
- 子任务组固定等待执行项的传输清单；accept/commit 都必须返回 void，失败通过抛错表达。提交仍等待实际完成，不将取消误表述为回滚。
