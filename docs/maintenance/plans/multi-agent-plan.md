## 1. 目标与依赖

Core 提供组织子执行的通用机制，App 决定组织哪些业务任务。支持一个主智能体委派有边界的专业任务，子执行隔离上下文、状态与工具范围，并遵守请求总预算、取消、授权调用和结果提交保证。单智能体仍是有效的独立使用方式。

Banker 的角色分工、功能拆出清单及接入批次以 [Banker 多智能体规划](../../../../main/docs/banker-app/multi-agent-plan.md)为准，Core 不维护第二份业务角色枚举，也不识别材料、产品或案件名称。

当前 Engine、ModelRunner、工具注册、上下文、取消与诊断可以复用。接口收敛后逐项核对实际缺口，不因本规划重新实现已有机制，不另造平行调度框架。

## 2. Core 的执行合同

以下保留首期设计要求；当前签名与已验证范围以现行 API 及实施记录为准，不表示每项都要增加新 API，后续目标也不能据此算作已交付。

| 通用能力 | Core 的责任与保证 | App 的接入责任 |
| --- | --- | --- |
| 委派与结果 | 提供发起、等待和返回子执行结果的统一合同；关联父子执行，明确完成、部分完成和失败 | 登记实际 handler、输入输出及业务完成条件 |
| 执行隔离 | 每个子执行拥有独立状态、上下文与工具调用作用域；不串用 journal、预览或完成状态 | 投影材料、选择角色工具与依赖，不默认复制完整对话 |
| 总预算与局部限制 | 父子模型消费归入同一总额度，局部上限不能扩大总额度；预留必要的父级收尾资源，耗尽时真实结束 | 提供业务预算配置和收尾策略，不能新建 runner 绕过统计 |
| 取消与截止时间 | 父取消传到子任务，子截止时间不超过父级；取消后迟到结果不提交 | 将 signal 传到真实服务；副作用对账和补偿仍由 App 负责 |
| 调度边界 | 首期支持一层顺序委派；拒绝越过允许深度。后续按需求增加受控并发 | 决定任务依赖和是否委派，不自行建立另一套执行循环 |
| 工具调用与授权端口 | 子调用沿用注册、校验与授权合同，不允许通过委派获得额外能力 | 真实账号、资源归属与操作许可由可信服务逐次校验 |
| 结果与错误 | 区分有效结果、部分结果、取消、超时、预算耗尽、协议和执行失败；明确传播边界 | 校验来源与业务完成性，决定补查、询问或终止，不伪造成功 |
| 诊断关联 | 可关联请求、父执行、子执行、工具调用和模型消耗；沿用既有诊断开关 | 管理输出、隐私、存储与保留期，不默认保存内部过程正文 |

共享预算与子执行隔离一起维护。直接共用一个有可变状态的 ModelRunner 不等于隔离；各自创建完整额度的 ModelRunner 也不等于共享预算。首期模型调用额度已由请求账本及子额度控制；检索、embedding、修复与轮次不能混成同一个计量单位。未来并行接入前必须明确祖先预算预留、原子计量、容量、并发取消、状态／输出隔离和提交顺序，不能解除当前拒绝后直接 Promise.all。

## 3. Support 与 Kit 将做什么

Support 在 App 侧提供可选的类型化角色清单、引用检查、上下文和依赖装配辅助，并可把委派包装为现有工具 handler。清单驱动模型可见描述和实际装配，不另建 Support 专属执行协议；Core 不导入 Support。

现有 Knowledge、Answering、Artifacts 等 Kit 可供专业 handler 单向使用，局部字段不升级为所有子执行的必需字段。Durable 已有产品批次消费者；将来专业子任务是否复用它，仍须先定义目标／材料版本、累计模型额度和 deadline、重新授权、幂等与对账及可恢复结果。持久化检查点、重放及副作用对账不因引入子智能体自动启用。

## 4. App 将做什么

App 拥有专业角色、语义委派策略、业务任务依赖、输入材料选择、来源和完成检查、可信授权、持久业务状态与最终呈现。主智能体通过已注册能力决定任务如何拆分；Core 只执行统一合同，不内置按业务名称分支。

长期规划的目标、约束、计划版本和实际进展由 App 作为可核验对象维护；不能只依赖子会话摘要。通用恢复机制与业务状态分别管理，新增记录范围和生命周期须单独确定，当前规划不授权扩展持久化。

## 5. 接入顺序与边界

1. 首期接口及 Banker 角色接入已完成，保留单智能体路径和现行统一合同，不保留旧签名兼容层。
2. B 继续核对真实消费者的生命周期、模型作用域和配置重复，不重新实现已有委派驱动。
3. R3—R5 分别补全家族、跨请求与并发合同后再确定实施范围；不能按新请求重置同一长期任务的累计额度。
4. 不提前实现递归、后台自动恢复／模型调度或智能体间自由互发任务，不扩大持久化范围。

实施时按具体疑问执行最小验证：总额度不可放大、父取消与子超时、迟到结果、工具权限、上下文与输出隔离、错误归属及单智能体路径的现行行为。真实模型质量与成本需另行明确验证，隔离测试不能替代效果证据。实施和验证结果见上方现行入口。
