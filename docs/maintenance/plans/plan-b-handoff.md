## 用户真正要求的简化

以下是本会话中用户反复明确的原则，必须用来判断自己的设计：

> 简化是在原来的基础上减省东西；学了简单的，再加一点就能接触更复杂的，而不是重新学习另一种风格。

> 只有三个：缺省、复用、代指，均来自内置或提前配置。

> Support 不是把裸配置套成对象，而是 Core 接口的最佳实践实现；其产物只需符合 Interface／type，不需要转换 plain object。

> 每个 route 函数是专用的，Workflow 的处理是公共的，公私要分明。

> App 注册监听，Core 触发执行事实；不是 Core 控制 App 输出，也不是 App 轮询查询进度。

这些摘录用于保留决策含义；具体接口仍要核对当前代码。不要把用户最初提出、后来已否定的方案重新搬回来。

## 必须吸取的教训

| 已否定的做法 | 应采用的判断 |
| --- | --- |
| 增加 defineAgentFlow／Standard DSL，再让用户重新学 | 在既有 Workflow／run 合同中省掉可确定的配置，保留渐进扩展 |
| 把一个 async 函数换成 call/saveAs 等多个字段就称为简化 | 看决策、概念、配置关系是否减少，不只数关键字 |
| 明明实例和依赖不变，每次 run 继续传 Workflow、模型、工具及诊断 | 按生命周期提前绑定，请求只给本次状态和必要 ID；并发执行状态仍隔离 |
| 提供 pick.xxx 或 routes 壳，换一种语法重复原判断 | 保留规范路由对象；route.xxx 固化常用逻辑、语义和复杂配置生成 |
| 为 route 默认值增加 ns 或 flag，要求 Workflow 识别函数产物 | 生成器输出完整普通配置；原始 conditionId 支持 {nid}.{rid}，Workflow 对所有对象统一展开 |
| Workflow 给部分路由补 to-target，升级成全局规定 | 默认由专用生成器决定；公共机制只做通用校验、占位和重复消歧 |
| 类型上说接受接口，实际用 spread 丢原型、丢 this，或返回类型承诺未保存 helper | 逐项读取合同、固定规范方法与原接收者；纯配置快照，App 服务不整体 clone/freeze；查询类型与真实投影一致 |
| 把所有回调错误、流和状态混到统一输出 | 共同类型统一概念；旁路观察与等待交付、执行结果与业务结论分别保留真实保证 |
| 为开发期旧接口、旧检查点、旧索引和旧日志保留迁移分支 | SDK 与 App 全新版本同步发布，只留当前合同，不考虑历史兼容 |

route 的当前约定：所有 to* 目标在前；route 为 route.to 别名；toIfEqual 比较路径和值，toIfEqualWith 比较两个点分路径（含 aaa.0.bbb）；多数现有 to* 习惯按目标生成 ID，但这是生成器习惯，不是 Workflow 约束。重复 ID 加缀，conditionId 通过原始对象支持的占位展开。不恢复 pick、routes 或旧根比较函数。

Core 与 Support 的缺省不同。Core 可选项反映非必需性或缺参时的合理值；Support 的推荐值和 handler 必须有场景依据，可以有多套推荐策略，且保留精确覆盖。类、接口实现、普通对象均是实现方式，不能将类实例当作比结构化接口更高级的必选路径。

## 工作模式

1. 先界定问题、所有者和生命周期，再列实际消费者与来源清单。先读注册／编排关系，再进入 handler，不靠全仓字符串替换改设计。
2. 对每批写一个同业务的“现状→最小接入→增加需求→自定义实现”对比，说明实际省掉的决策、参数或重复配置，以及仍由 App 决定的内容。
3. Core 与 Support 共用同一合同；能复用就复用，不造并行调度器、私有 DSL 或强制转换层。不要为分类完整新增目录、接口或自动门禁。
4. 每批按声明、实现、类型、真实 App、示例、文档和验证闭环。移除已被取代的旧路径；当前接口不以增加兼容别名交付。
5. 保留预算、取消、deadline、授权、真实回执、输入／输出校验、状态提交顺序和并发隔离。失败、未处理、继续、合法 undefined、暂态预览和最终完成必须区分。
6. 主会话统一设计、公共类型和集成验证；子智能体按清晰文件／职责边界工作，不同时改共享文件，完成后报告真实证据。可使用子智能体，本用户已授权协作。
7. 先源码推理，再针对具体疑问执行最小检查。修正测试不是放松合同；先确定失败是实现、旧 fixture 还是运行限制。通过后不重复跑全套。
8. 60 秒内保持有内容的进度沟通，继续自主实施，不一项一停让用户批准。只有真正缺失的产品决定／授权才询问，提问时继续不依赖答案的工作。

用户已全权授权 SDK 与两个 App 共同演进，也明确要求自检、自测。根 AGENTS.md 对检查频率、UI、数据和发布仍有效。不能用检查为理由打开 UI 或调用真实模型。
