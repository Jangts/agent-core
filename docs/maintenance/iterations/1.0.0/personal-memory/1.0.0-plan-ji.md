# Agent Core 1.0.0 己方案：有来源的个人记忆

## Accepted scope

The two Apps need the same pure snapshot validation, evidence association, replacement and bounded projection. Add the optional `@jangts/agent-core/kits/memory` entry. Core execution contracts remain unchanged: ModelRunner already supplies cancellation, bounded calls and validated outputs. The Kit never imports App storage, identity or configuration. Apps own source authorization, leases/CAS, retention and scheduling.

## Contract audit

- Input: registered allowed kinds and App-authorized user sources. Exact quotes are transient and discarded after source association. This proves an assertion was made, not that it is objectively true.
- Output: copy-on-write versioned snapshots; revisions and source identities survive replacement. Old sources cannot overwrite newer statements. Invalid operations fail before publication.
- Storage: optional nested snapshot; old summaries remain explicitly unverified legacy content. No fabricated evidence and no raw transcript copy.
- Projection: account/session scope filtering, expiration and a 300-codepoint preference projection, plus at most three relevant entries. Feedback never establishes truth or authority.
- Maintenance: availability is checked by App ports; missing evidence is recorded, not reconstructed. Model review only uses authorized retained sources. Publication and watermark advancement are atomic in each App.
- Boundedness: 16 changes per invocation, 64 active entries, 128 total versions. Older active overflow becomes needs-review; new explicit statements may reactivate it. Retirement floor prevents old-source resurrection.

## Rejected alternatives

Do not add memory fields to Engine state, introduce a second workflow engine, persist model reasoning, expand transcript retention, share memory across accounts, or migrate legacy summaries into verified facts. No new database service or vector database is required.

## Verification obligations

Test forged evidence, source-side instruction injection, older-source replay, correction/retraction, expiry, session isolation, unavailable evidence, malformed persisted snapshots, capacity, cancellation, concurrent publication and pending watermarks. Static checks and offline fixtures do not prove real-model extraction quality.

## 应用接入与验收范围

cafe使用SQLite原子发布和有效租约，Banker使用账户作用域Level记录与revision CAS。两端只自动登记个人preference/goal，不自动发布业务经验、事实或流程。Core执行合同不变；公开Memory Kit具有明确个人记忆约定，不声称任意kind都具有相同摘要行为。正式合同见开发指南memory-and-learning及两端chat-memory文档。

低信任legacy有固定过渡期：cafe14天，Banker60天，之后不再注入。明确纠正可删除精确旧片段。原文保留政策不变。分钟增量增加调用机会，单轮8次调用上限不是月度费用承诺；没有新增消息或待复核事项时不调用模型。

审计角色、问题处置、影响面及实际验证见[己案审计记录](1.0.0-plan-ji-review.md)。编译和替身测试不证明真实模型的语义归属、隐私排除或线上收益。

退休时间下界是保守收敛策略：清退版本后，不再从该下界及之前的旧来源重建缺失条目，即使某条更早的内容当初未被记住。新的明确表达仍可创建条目。此取舍避免有限墓碑清退后的旧偏好复活，不承诺无损保存全部历史。

App首次维护即对无新增原文的旧短摘要纯程序建立过渡快照；cafe通过同源schema仅登记account范围，Banker对goal程序限制session。来源页通常100轮，首个同时间戳组完整扩展至1000轮；超限明确退避，不用空来源假装进度。
