# 乙计划协议适配与验证矩阵

核对日期：2026-11-25。本记录对应当前工作区实现，不是全部厂商生产兼容承诺。DeepSeek 三协议具备有限真实证据，其他格以离线及 MockGPT 消费者为证据，详见[实施验收](1.0.0-plan-yi-implementation.md)及[DeepSeek 记录](1.0.0-yi-deepseek-validation.md)。

## 已实现接入合同

`createModelProvider` 接受 protocol、baseUrl、apiKey、model，以及可选 stream、maxOutputTokens、request、headers、scope。protocol 为 chat-completions、responses、messages、generate-content、interactions。baseUrl 包含 API 版本前缀，适配器追加对应资源路径。凭据始终通过请求头传递。默认 SSE，stream:false 使用完整响应；普通 stream 投影旧文本／函数片段，streamEvents 提供完成、用量和受控续接事件。

scope 是宿主明确提供的身份作用域；只有显式 scope 才产生可回传 continuation。续接校验协议、模型、端点、版本及作用域，凭据不进入续接。调用方使用完整历史加该状态，适配器回放逐轮原始块，保留签名／推理状态；不默认启用厂商持久会话。

| 协议 | 请求/响应目标 | 工具模式 | 结构化目标 | 证据与边界 |
| --- | --- | --- | --- | --- |
| Chat Completions | messages、choices；SSE delta | auto/required/none、多调用 | JSON object、JSON Schema | 完整 HTTP／SSE fixture 与 MockGPT；DeepSeek Chat 有限真服务见专项记录 |
| Responses | input/output项、SSE output item与参数delta | auto/required/none、多调用 | JSON object、JSON Schema | 完整 HTTP／SSE fixture 与 MockGPT；DeepSeek Responses 有限真服务见专项记录 |
| Claude Messages | system独立、内容块；content_block事件 | auto/any/none、多调用 | output_config.format 原生 JSON Schema | 完整 HTTP／SSE、签名多轮 MockGPT；DeepSeek Messages 非思考工具两轮通过，原生 Anthropic 真服务未验 |
| Gemini generateContent | contents/parts、candidates；SSE候选 | AUTO/ANY/NONE、多调用 | responseMimeType/responseJsonSchema | 完整 HTTP／SSE、thoughtSignature 原始 parts 多轮 MockGPT；厂商真服务未验 |
| Gemini Interactions | stateless user_input/model_output/function_call/function_result步骤；step事件 | auto/any/none、多调用 | response_format JSON MIME/schema | 完整 HTTP／SSE、无状态 thought 步骤多轮 MockGPT；厂商真服务未验 |

原生严格 function schema 在 OpenAI 两协议及 Claude Messages 请求映射；Gemini 两协议明确拒绝 strict:true，不宣称本地验证等于上游严格约束。可移植函数名采用稳定公共交集；非法名称、重名和不可移植schema关键字在I/O前定位拒绝。当前支持对象、基本类型、properties、required、items、enum、additionalProperties及说明；更多方言仍待P0逐项核定。

输入有序 parts 为已实现 wire 映射；按 catalog 区分允许模态。URL/data URL 与宿主字节／引用资源准备已接线；远端下载大小和上传行为依宿主端口，未逐媒体实测，不能将“类型可表达”记为端到端通过。托管搜索接入见后节；后台、Batch 和实时由独立生命周期工作包实现；此工厂不擅自执行本地工具。

## 显式厂商托管搜索

工厂通过 hostedTools 传入协议原生定义，必须同时提供 authorizeHostedTools。授权回调在每次生成请求前执行；抛错或返回 false 则不发生成请求，成功返回 void／true 放行。未配置的远端工具输出明确拒绝，不能由上游响应自行扩大权限。

onHostedToolEvent 是可选的私有观察回调，逐次等待；source 固定为 provider，phase 区分 started／delta／completed／sources，data 保留远端调用、结果和来源信息。回调抛错会中止本次结果消费，不重试生成，也不表示远端执行撤销。原始结果、查询、密文引用和来源不进入 Core 通用日志、业务 journal 或本地 ToolRegistry 回执。每个请求使用独立 decoder 和事件队列。

| 协议 | 原生配置及实际处理 | 当前证据 |
| --- | --- | --- |
| Responses | hostedTools: [{type:'web_search'}]；接收 web_search_call 及原生搜索进度；请求来源 include，保留 sources 与引用 | 完整响应和 SSE；每请求授权、拒绝无网络、回调失败无重提的离线 fixture；未真实验证 |
| Messages | hostedTools: [{type:'web_search_20250305',name:'web_search',max_uses:1}]；接收 server_tool_use／web_search_tool_result／引用增量；encrypted_content 原样保留在私有续接中 | 完整响应和 SSE；未真实验证 |
| Interactions | hostedTools: [{type:'google_search'}]；接收 google_search_call／google_search_result 步骤和原生 delta；保留来源及搜索建议 | 完整响应和 SSE；未真实验证 |

当前明确只交付上述搜索格。Responses code_interpreter／MCP、Messages 动态过滤搜索版本默认包含的 code execution，以及其他厂商托管能力尚未实现，继续标为未完成，不能据搜索接入宣称全部托管工具可用。Messages pause_turn 继续作为 incomplete 处理，不冒充生成完成；自动继续远端循环不属于当前搜索适配器保证。

官方依据：[OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)、[Claude Web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)、[Gemini Google Search](https://aistudio.google.com/docs/google-search)。核对日期 2026-11-25；Claude 基础版本与自动动态过滤版本分别核对，未将后者隐含执行权授予基础搜索配置。

## 显式供应商扩展与 DeepSeek 思考状态

工厂及共同 prepareModelRequest 支持 requestBody 兼容配置。扩展在构造／准备时深克隆和冻结，不能覆盖模型、身份、输入、指令、流、工具及选择、输出预算、输出格式、续接和存储策略等 Core 字段。output_config 扩展只可设置 effort，与 Core 生成的 format 合并。此能力不另建供应商循环，也不以协议支持冒充具体模型能力已验证。

DeepSeek 非思考配置：Chat Completions 与 Anthropic Messages 使用 requestBody:{thinking:{type:'disabled'}}；Responses 使用 requestBody:{reasoning:{effort:'none'}}。DeepSeek Anthropic 目前仅支持 output_config.effort，不能将 Claude 的原生 format 支持视为该兼容端点已支持。

Chat Completions 的 reasoning_content 属于私有 continuation：完整响应保留原 assistant，SSE 合并私有推理及调用片段，跨工具轮累计以前的 assistant 状态。回放校验端点、协议、模型、scope 与历史位置、文本和工具调用身份；历史裁切或改变导致锚点不匹配时明确拒绝，不能把旧推理放到另一条消息。推理不投影为用户文本，也不进入普通事件／journal。使用工具时由宿主持有并回传 continuation，不要求业务拼装 reasoning_content。

依据：[DeepSeek Thinking](https://api-docs.deepseek.com/guides/thinking_mode/)、[DeepSeek Anthropic Compatibility](https://api-docs.deepseek.com/guides/anthropic_api/)，核对日期 2026-11-25。真实验证由独立授权的 live 工作包记录，本矩阵不提前声明通过。

## 多轮私有状态锚定

所有五协议统一使用 data.history 与 data.turns，分别保存规范化可见历史前缀及逐 assistant 轮的原始 native 块。工厂从实际输出事件收集可见文本、有序媒体与调用参数，不要求 App 人工生成或比较锚点。下一次请求在网络调用前核对旧 system／user／assistant／tool 历史、调用关联和各轮位置；改写、裁切、缺锚点旧开发态 state 明确拒绝。该新增形状尚未发布，不声称兼容无锚点的旧临时数据。

回放保留所有旧轮的推理密文、thoughtSignature 和内容块顺序，按协议原始 wire 偏移逆序替换，不只替换最后 assistant。Chat 仍仅将私有 reasoning_content 放回其对应轮。可见 assistant 文本仅规范化最外侧前后空白，兼容默认文本 transport 的 trim；内部空白不变。分片文本合并、content/images 与等价 typed parts 使用同一可见投影，媒体语义顺序保留。原始 native 块不按该规范化改写。

私有 continuation 上限为 JSON 序列化后 1,048,576 字符，生成及回放均检查；超过时明确失败，宿主应缩短会话或重建可移植历史，不将超限 state 投入普通诊断。状态依然只经私有 onContinuation／宿主存储传递，不进入通用日志、journal 或托管工具观察回调。

## 显式端点能力约束

可选 capabilities:{modalities,tools,jsonSchema} 只缩窄协议可表达能力，不按模型名、URL 或品牌推断，也不接受 verified 等验证标记。宿主可明确声明已知端点限制，例如 DeepSeek Messages 的 jsonSchema:false；此时 outputSchema 以及依赖原生对象 schema 的 Messages／Interactions json 模式在 I/O 前拒绝。Chat Completions 的 JSON object 模式与 JSON Schema 分开，jsonSchema:false 不禁用其独立 JSON object 能力。模态必须是协议清单子集，tools:false 禁止所请求的本地工具 schema 和托管工具；共享准备入口供普通调用及生命周期接线复用。
