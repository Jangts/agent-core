## 实际交付与阶段边界

P0—P3 的有限矩阵已实现，P4 已取得下表所列本地、包体与 DeepSeek 证据。未验证厂商云端及未实现托管能力保留缺口；本记录不宣称整个 1.0.0 已完成或所有厂商功能等价。

- Core 保留旧文本／函数片段消费合同，新增受控完整事件、有序媒体输入、正常终态检查和独立 continuation。Runner 统一拥有请求／子执行预算、取消、清理域和生命周期元数据诊断；失败结果不发布临时续接状态。operation-only 和 realtime-only Provider 可直接构造 Runner，不需要伪造 stream，原型方法的 receiver 与私有状态在绑定及子执行中保留。
- Support 工厂提供五协议 HTTP／SSE、可移植函数工具与 JSON／schema；能力只可显式缩窄。扩展 requestBody 不能覆盖 Core 所有字段。五协议续接校验完整历史前缀、逐 assistant 锚点和 scope／endpoint／model，私有签名和推理块跨多轮原样回放。
- 后台 Responses／Interactions 与三类 Batch 共用请求准备和中立解码；任务 reserve／save 由宿主实现，身份、未知提交、逐项结果关联和当前授权由公开合同约束。query／read／cancel 为零生成的有界动作，不因取消本地等待就宣称撤销远端执行。
- Realtime／Live 提供注入双工、真实 WebSocket 接线及 WebRTC SDP／datachannel 接线。手动轮次和阻塞工具组受 Runner 准入；tool-wait 与最终 completed 分开。OpenAI 全组结果及原 response.done 后发送一次 response.create；Gemini 全组结果经一次 toolResponse 原生续答，触发前完成预算和授权。标量结果规范化为 JSON 对象，for-await 中 await session.tool 不形成死锁。
- 三类显式厂商搜索保持授权和私有事件，不转成本地执行回执。资源准备支持有序 URL／字节／宿主资源引用；续接存储为可替换宿主端口，不伪装持久数据库。
- 双语使用手册、公开示例、README、Skill、API 参考与 pages 来源生成已同步。五协议示例使用同一授权 ToolRuntime 循环；两个后台示例直接使用真实可选端口 Provider。

详细范围见[协议矩阵](1.0.0-yi-protocol-matrix.md)、[生命周期记录](1.0.0-yi-lifecycle-design.md)与[真实验证](1.0.0-yi-deepseek-validation.md)。

## 保留缺口及交付约束

- 尚未实现 Responses code_interpreter／MCP、Messages 动态过滤隐含的 code execution 等全部托管能力；目前只承诺明确列出的三类搜索。不能据五协议接入宣称支持每个厂商产品或所有调用风格。
- 原生严格 schema、同轮多工具、所有媒体格式、后台／Batch 与实时的厂商真服务尚未逐格验证。WebRTC 使用 fake peer 验证控制链，未进行设备、真实远端 SDP 或媒体质量验收；自动 VAD／NON_BLOCKING 工具明确拒绝。
- 宿主持久原子性、实际主体和业务授权仍由宿主提供；本地预算不承诺约束厂商内部不可观察费用。无真实业务写入或容量测试。
- 较早全 SDK 快照 1188 项中为 1171 通过、2 失败、15 跳过；两个失败位于并行丙案 result-review／review-decision，未修改其实现或断言。本次 279 项成功不取代丙案修复及最终同候选全局验收，也不据旧快照断言其当前状态。
- 丁负责长期命名、稳定合同与旧包升级／同候选全局收口；乙未提前实施丁的全量改名。当前 tarball 来自包含其他方案改动的共享工作区，指纹只标识本次实际输入，不代替甲丙丁验收。
- 保持版本 0.9.0；未提交、推送、发布、部署或修改真实存量数据。临时检查文件只用于当前排障，必要结论进入本记录后按任务范围清理，不清理其他会话文件。
