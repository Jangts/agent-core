# 乙计划生命周期实现记录

日期：2026-11-25。本记录区分已实现接线与尚未完成的协议范围，不是完整乙计划验收。

## 公共接线

`runModelOperation(provider, request, ports, signal)` 的 `ports.run` 绑定请求域 Runner 的 `runOperation`。submit 以 item 数量准入，再通过宿主原子 reserve 独占操作身份；query/read/cancel 使用独立有界 Runner 操作，生成调用数为零。每次动作执行当前 authorize，结果按 operation/scope/protocol/endpoint/model/item 身份校验。提交异常只有 provider 调用 markDispatched 后才记录 unknown，禁止将本地准入失败当远端已接纳；重复预留拒绝，不自动重提。宿主 save/reserve 是持久排他合同，包内未伪装数据库。

`waitModelOperation` 采用显式 maxQueries/intervalMs，计时器在取消或完成时释放，不在函数返回后留下轮询运行权。取消动作应由宿主用独立 cleanup signal 发起，不能传入已 aborted 的原执行 signal。

`openModelRealtime` 在 Runner 准入内连接及发送，逐次当前授权、有限帧数和帧大小，关闭释放资源。工具发送不自动执行工具，仍经上层注册工具和授权。中断推进 generation，迟到事件必须经 generationOf 明确关联；缺乏关联的中断后事件丢弃，不把旧事件标成新轮次。协议级响应 ID 映射由 openProtocolRealtime 提供，普通调用方不手写 generationOf。

## 已实现 Support

createBackgroundModelProvider 接受统一 messages/options，复用 prepareModelRequest 编译 Responses／Interactions。submit/query/read/cancel 的 action 相同；pending 不返回生成成果，完成时 value 为中立内容／工具事件，usage 归一化，continuation 独立于可见结果。

- createOperationHttpProvider：Responses/Interactions 后台提交和查询、远端取消；OpenAI/Anthropic/Gemini Batch 端点选择与原生提交 payload。Gemini Batch 使用 models/{model}:batchGenerateContent；非提交使用远端批任务名称。Anthropic results 使用 JSONL 读取。
- createRealtimeProtocolProvider：OpenAI session.update 与 Gemini setup；realtimeInput/realtimeToolResult 提供文本及工具结果帧。
- connectModelWebSocket/createWebSocketDuplex：可注入 socket factory，实际打开、发送、消息读取、取消、关闭，有界入站队列、出站 bufferedAmount 与帧大小限制。
- connectModelWebRTC：实际 offer/local SDP、宿主交换 answer、remote SDP 与 datachannel 接线；媒体设备、轨道和临时凭据由宿主提供。

## 后续补强与实际证据边界

createBatchModelProvider 已补统一 items{id,messages,options} 编译，复用会话协议请求映射；OpenAI JSONL 上传及 output/error 文件读取，Anthropic 逐项 requests/results、Gemini inline 请求和返回映射；结果以统一 ProtocolDecoder 事件关联 item ID，缺项报告 BATCH_ITEM_MISSING。实际云端文件存储和计费未验证。

openProtocolRealtime 已补统一 text/audio/commitAudio/tool/interrupt/events/close：OpenAI 使用待创建轮次队列与 response ID 映射隔离中断前响应；Gemini 用 interrupted ack 屏障隔离旧内容。文本、音频片段和工具结果发送不自动重复扣生成次数，显式 response.create／结束音频轮次分别准入；每轮 generation 独立推进。实时响应解码为文本、音频／媒体、工具及完成事件。高级实时接线默认手动轮次，setup 禁用自动生成；显式自动 VAD 配置拒绝，避免服务器自动产生未准入轮次。远端内部费用不宣称本地硬上限。

WebRTC 轨道接入和真实媒体／全部厂商实测未执行。Gemini responsesFile 下载已按官方 /download/v1beta/{file}:download?alt=media 实现，inline 和 JSONL 文件结果均强制使用显式 item key 关联，拒绝按位置猜测。Batch 与普通调用共同使用 prepareModelRequest 预检和续接回放，拒答／截断项记 failed。跨宿主持久账本实现与完整多模态上传由总整合方按承诺矩阵逐项验收。本记录不替代 P3 验收。

## 授权时限及 WebRTC 接线复查

operation 与实时 connect/send 的宿主授权经同一 Runner 的独立零生成预检执行，action 为 authorize。回调接收有界 signal；即使宿主授权 Promise 不返回，本地取消或时限仍可停止等待；未通过授权不进入 reserve、网络或生成额度扣除。取消／清理动作的授权沿用独立 cleanup 域。已经开始但未 settle 的宿主回调仍保有门闩，避免本地停止等待后重新并发授权；不把取消等待声称底层回调已被强制终止。

新增四项确定性用例：挂起 operation 授权取消、挂起实时 connect 授权取消、挂起实时 send 授权取消，以及注入 peer/datachannel 的 WebRTC SDP／发送／收取／lifetime 关闭控制链。用例执行真实接线函数、使用 fake 端口，不代表真实媒体或远端 SDP 验收。最新共 18 项生命周期 fixture，由总整合方统一构建后验证。

实时 close 通过 Runner 零生成 cleanup 操作执行，宿主异步关闭受 cleanup 时限和纯元数据诊断约束；重复调用等待同一 closing Promise。新增挂起 close 的定向用例，验证超时拒绝、只调用宿主一次且不消耗生成额度，最新生命周期 fixture 共 19 项，待总整合方统一构建验证。

## 实时工具结果后的模型续接

统一 `tool(id,name,value,generation)` 按原提案代次缓冲并返回，不等待同一 for-await 消费循环中的后续帧。OpenAI 在原 response.done 和该组全部结果齐备后，批量回传 function_call_output，再通过 Runner 准入一次新的 response.create；原响应尚活时不提前创建。Gemini 先登记同帧所有提案，结果齐备后通过一次 toolResponse 的 functionResponses 列表回传；官方 Live API 在工具结果后原生继续，不伪造 response.create 或新用户输入。

续接进入新 generation，生成触发帧发送前先扣除生成准入；Gemini 因 toolResponse 本身可能触发生成，预算不足时整帧不发送。OpenAI 已发出的工具结果不重复发送，可在本地政策／预算调整后显式 respond 重试未触发的续接；发出后的未知网络结果不自动重提。工具阶段使用 tool-wait 事件，不冒充最终 completed；仅没有待执行工具的模型终态为 completed。旧代次结果和中断后的迟到提案不能启动新生成。默认采用阻塞工具组，显式 NON_BLOCKING 配置拒绝，避免未定义的并发轮次语义。

新增五项真实 Core 控制链 fixture：OpenAI 多工具结果后最终文本、续接额度耗尽无新 response.create、Gemini 批量 toolResponse 后最终文本、后续响应复用同 call_id 拒绝旧代次结果、中断迟到工具不重启。最新生命周期用例共 24 项，未在子代理内 emit 或执行。

官方依据：[OpenAI Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)、[Gemini Live tool use](https://ai.google.dev/gemini-api/docs/live-tools)。前者要求工具结果后请求新的响应；后者示例在 sendToolResponse 后继续接收下一段模型输出。

Gemini FunctionResponse.response 统一保持 JSON 对象：业务工具标量、数组及空值包装为 `{result: value}`，普通对象保留；单结果 helper 和批量续接共用该归一化。独立 toolCall 帧先注册完整组并发一次 tool-wait，不依赖 serverContent.turnComplete，也不冒充最终 completed。新增标量结果与独立阶段事件控制链用例，生命周期 fixture 共 25 项，已包含于最终 279 项受影响回归（273 通过、6 项真实服务跳过、零失败）。此前各轮数量仅为当时阶段记录。

最终 MockGPT 公开消费者另外验证 OpenAI／Gemini × 注入双工／真实本机 WebSocket 四格，从工具事件内 await session.tool 到最终回复，校验授权执行一次、两次生成、唯一续接帧及单条用户输入。与生命周期等组合共 113 项零失败零跳过，数量和范围见[实施验收](1.0.0-plan-yi-implementation.md)；不是厂商真实服务或真实媒体证据。
