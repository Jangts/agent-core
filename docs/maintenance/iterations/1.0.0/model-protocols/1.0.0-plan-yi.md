# Agent Core 1.0.0 乙计划：统一模型接入与交互

日期：2026-11-25。修订：第三版。状态：经七方设计审计及原提出方分歧对齐的方案，尚未实施或运行验收。基线：当前工作区源码。乙计划是 1.0.0 的部分任务，与[甲计划](../execution/1.0.0-plan-jia.md)共同演进，不代表整个版本完成或发布。

七方意见、源码证据和二轮处置见[设计审计与重设计记录](1.0.0-plan-yi-review.md)。

## 1. 目标与交付原则

在 agent-core 包内支持主流模型 API 协议与调用方式，让上层持续使用一致的模型调用、工具注册、结果消费、取消和诊断体验。同类任务切换适配器主要调整协议标识、端点、模型及少量能力参数，在相同生命周期、目标端点具备所需能力且业务定义处于可移植范围内，不修改业务 handler、工具 schema、授权流程、Agent 循环或结果读取代码。普通调用切换到批量或实时属于任务形态变化，使用对应统一入口，不承诺只换协议即可转换业务形态。

“兼容集中在 Runner 层”指 Runner 所拥有的模型契约和围绕它的 Support 适配器，不指把所有厂商逻辑放入 runner.ts。Core 不导入具体 Provider 或 Kit，不建设第二套调度器。必要的公共消息、事件、状态及能力契约可以扩展；Engine 和业务流程不按厂商分支。

改动默认控制在 packages/agent-core，包括源码、Support、可选 Kit、公开示例、测试、开发资料和维护记录。应用只在确有公开契约迁移或验收需要时作最小接线调整。相邻文档站、模拟服务涉及源码输入或公开契约时同步核对；必须修改时逐项目遵守 AGENTS.md，不以 Git 边界遗漏契约，也不借本计划重构其他工程。

### 验收底线

- 相同能力的协议切换保持调用及结果结构一致，不要求 App 手写厂商请求、解析流或维护续接字段。
- 高级能力按任务显式启用，不把后台任务、实时连接或持久状态变成普通文本调用的必填配置。
- 适配器不能伪造上游能力。缺失必需能力在 I/O 前明确拒绝；不静默丢弃参数、推理状态、工具结果或多模态内容。
- 保留预算、身份隔离、工具授权、取消、诊断、输入输出校验及真实副作用保证。
- 用户已授权设计本方案；本文不是实施、真实付费调用、发布或部署的完成记录。

## 3. 支持矩阵

“主流”以本节清单及实施时固定的官方版本为准，不承诺任意厂商、任意模型或未来协议自动兼容。支持协议不等于支持该厂商全部产品接口；能力逐模型和端点声明。

### 3.1 API 协议

| 协议族 | 乙计划交付 | 统一接入目标 |
| --- | --- | --- |
| OpenAI Chat Completions | 复用并补强独立适配器 | HTTP 完整返回及 SSE；工具、JSON、会话 |
| OpenAI Responses | 独立适配器 | 输出项／事件、工具结果回传、续接状态、后台响应 |
| Anthropic Messages | 独立适配器 | 内容块、工具调用／结果、推理签名及缓存相关参数 |
| Gemini generateContent | 独立适配器 | contents／parts、候选、函数调用、多模态与必要签名 |
| Gemini Interactions | 独立适配器 | interaction、会话续接、任务与工具交互 |
| OpenAI Realtime 与 Gemini Live | 独立实时适配器 | 同一实时会话合同内的输入、输出、打断、关闭及工具交互 |
| 兼容服务 | 显式选择上述协议与端点配置 | 兼容差异由 capability/profile 声明，不靠品牌、模型名关键词猜测 |

DeepSeek、百炼等服务优先复用协议适配器。仅在真实 wire 差异不能由少量声明式 profile 表达时新增适配实现，不为每个品牌复制一套循环。专用图像、视频、语音生成及 Embeddings 等独立产品 API 不因“主流协议”被自动纳入；会话协议中的多模态内容和实时音视频属于本计划。

### 3.2 有限承诺与逐格验收

P0 固定“协议版本／端点／模型 profile × 能力 × 生命周期”矩阵，不把上述两张清单理解为全部组合。每格分别记录目标（必交付原生／显式替代／上游不支持）、实现状态、验证级别、证据日期及参考场景。尚未调查的目标标为待核对，不能标为上游不支持；未验证与不支持不是同一状态。每种会话协议至少交付文本与本地工具两轮往返；JSON、schema、多模态、续接、托管工具按官方支持逐格确定，不能全部靠“拒绝”关闭承诺。

后台至少覆盖 Responses 和 Interactions 官方支持的执行路径；Batch 覆盖 P0 核定提供官方批处理的协议族；实时覆盖 Realtime 与 Live。P0 必须给出具体端点、模型、模态和场景，不以一句“按能力”代替交付范围。上游确实不支持的组合不补造原生能力；已确定必交付格若受阻保持未完成，减少承诺须明确报告。

### 3.3 调用与交互方式

| 方式 | 上层体验 | 实现要求 |
| --- | --- | --- |
| 普通文本、图片等多模态会话 | 统一输入、结果及事件 | 简单文本沿用便捷写法；内容类型明确 |
| 非流式与 SSE | 同一 call 路径和结果，事件订阅可选 | 非流式转统一事件，不伪造逐 token 增量 |
| 原生工具调用 | 统一工具定义与结果关联 | 单选择与会话多调用分别保留；支持 prose 与 calls 共存 |
| JSON 操作选择 | 同一能力目录与执行权限 | 使用现有 JSON interaction；显式选择，不作为隐式降级 |
| 结构化输出 | 统一 schema 与验证结果 | 区分原生严格约束、JSON 模式及本地校验，不能宣称等价保证 |
| 后台任务 | 统一提交、等待、查询、取消及恢复 | task handle 由包内封装，轮询／事件消费不外泄到业务循环 |
| 批量调用 | 可选 Batch Support 的统一提交／查询／结果关联 | 逐项关联、部分失败和账本独立；上游无 Batch 时明确拒绝，不暗中并发代替 |
| 实时会话 | 同一实时入口、输入／事件／打断／关闭 | WebSocket／WebRTC 接线在 Support；媒体设备和播放宿主由 App 提供 |
| 厂商托管工具 | 统一内容与执行事件，显式启用 | 区分远端执行与本地工具提案，不伪造本地执行回执 |

普通调用、任务、批量和实时是不同生命周期，分别有一致的公共入口；不要求它们使用完全相同的方法签名。相同生命周期内的厂商切换不得改变业务编排。

## 4. 责任划分与结构

| 所有者 | 责任 |
| --- | --- |
| Runner 及 Core 模型契约 | 通用输入输出、能力要求、生命周期、执行身份、预算、取消、终态、journal 与诊断 |
| Provider Support | 厂商鉴权、HTTP／SSE／实时协议映射、请求参数、错误、状态封装和媒体协商 |
| Interaction／Transport Support | 文本、单选择、会话工具及结构化输出的编译、收集、解析与验证 |
| 可选 Kit | 可复用的 Assistant／Agent 会话组织或媒体交互逻辑，使用现有 Core API，不取得新的授权或调度权 |
| App | 凭据与存储注入、用户身份、业务工具与权限、媒体设备、交付界面 |

普通生成、operation、batch、realtime 按可选能力接口组合；能力绑定贯穿 settings、binding、bind 和 child：每个启用方法只读取一次、保留原 receiver 与私有状态，不能只快照 stream 而丢失可选端口，也不冻结宿主实例本身。简单 Provider 仅实现普通生成，不强迫实现全能接口或空方法。模型执行保证只有一套，不为每个生命周期复制 Runner 或另建平行调度器。

不强制新增 Kit。普通切换若必须引入 Kit 或重写 handler，先修正公共模型边界。App 仍可自定义 Provider；不以官方适配器注册表限制扩展。

## 5. 统一接入设计

### 5.1 配置和能力目录

新增一个 Support 模型接入工厂，集中接受 protocol、baseUrl、apiKey、model、通用 defaults 和类型化协议扩展；具体公开符号名在 P0 对照现有 API 约定后确定。不同适配器也可以提供具名构造器，但最终返回相同 Core 契约。

一个声明式协议目录登记构造器、支持的生命周期、参数映射和能力说明；interaction 目录登记结果模式与能力要求。能力协商由协议、已验证端点／模型 profile 和调用要求共同决定；未知能力不推定支持。通用能力清单包括内容模态、流、工具选择、多调用、严格 schema、续接、托管工具、后台／批量／实时及用量。避免把所有组合穷举成类型或在 Runner 中堆厂商条件分支。

上层配置示意，仅表达设计意图，不是已存在的公开 API：

```ts
const provider = createModelProvider({
  protocol: 'responses', // 切换为其他协议时保持业务调用和工具定义
  baseUrl,
  apiKey,
  model,
  defaults: { maxOutputTokens: 2048 },
});
const runner = new ModelRunner({ provider });
// 继续使用统一的普通调用、transport 和工具注册方式。
```

能力目录分别表达协议可表达性、端点／模型验证状态、宿主授权和可执行限额。profile 不是权限或验证事实来源，显式覆写不能提升权限或把未验证标成已验证；网络预检也不能保证远端不拒绝。

工厂根据已绑定 Provider 与任务要求提供普通文本／工具场景的默认接线，不要求开发者重复维护 protocol、profile、interaction 和厂商 ID。JSON 替代仍需显式选择；显式策略覆写不改变 Core 的执行保证。

通用参数由适配器映射；协议专有参数放到类型化扩展中，冲突字段拒绝覆盖受 Core 保护的身份、输入、流、预算和权限。profile 显式配置优先于已验证默认值；不得通过自由 requestBody 绕过能力检查。能力必需项不支持时拒绝；允许替代的策略必须由调用者显式启用，并在 trace 记录。

### 5.2 可移植工具与结构化合同

P0 固定可移植 JSON Schema 子集、工具命名和参数编码规则；包含对象、基础类型、必填项及声明支持的嵌套／枚举约束，具体关键字以协议交集与真实样例确定。超出子集通过显式协议扩展提供，编译器在 I/O 前给出工具 ID、schema 路径及不能表达的约束，不能静默删约束或降低 strict 保证。业务工具 ID 保持稳定，wire name 由 Support 映射，碰撞与非法名称在注册／准备阶段拒绝。

JSON 对象模式、上游 schema 约束和本地 schema 校验分别记录保证等级。本地校验始终发生在本地工具授权／执行之前；显式允许的格式修复消耗真实调用额度，不重做已完成副作用。只有满足同一能力合同的协议切换才承诺工具定义不变。

### 5.3 消息、输出和终态

保留简易文本输入，内部归一化为有序 typed parts。适配、快照、回放和结果投影保持文本、媒体、工具调用及工具结果的语义顺序，不因按类型存储而重排。P0 逐协议固定文本、图片、音频、视频、文件及工具结果的输入／输出方向与支持目标，具体格式和缺失能力按承诺矩阵处理，不承诺所有端点支持全部模态。增量输出区分文本、工具参数、媒体、状态、用量与终态，Runner 先消费生命周期、用量和受控状态事件，再按 transport 声明向 collector 投影内容／工具事件；旧文本、native／JSON 与自定义 collector 无需识别新厂商事件。必要桥接留在包内，未知必需事件拒绝，已明确可忽略的元数据可以跳过。工具调用片段按稳定调用身份关联，不假设各厂商 index 或分片边界相同。

底层完成信封包含完成状态、可见内容、调用提案、用量与受控状态引用；公开结果按 transport／生命周期投影。普通文本仍返回现有 string，注册 transport 保留精确泛型，session 保留自己的结果类型，不强迫业务判别全协议大 union。截断、拒答、等待工具、后台处理中与成功完成分别表达，不把断流当成功。现有文本和 session 结果可通过投影保持易用；不能为兼容旧 collector 丢掉必须保留的信息。新增字段和事件先检查现有 exhaustive switch、快照和公开导出的消费者。

输入资源使用明确的 URL、字节或宿主资源引用合同；各端点采用其实际支持的资源形式。Support 在 Runner 准入后的有界执行中，经宿主端口完成必要的解析／上传，宿主拥有上传存储和保留策略，Core 不自带资源仓库。资源准备与实际生成分开计量，准备前执行身份、资源形式、大小和权限预检；准备过程受取消及限额约束，冻结实际生成输入后再执行对应计量和生成准入，准备失败不触发生成，也不将已发生准备开销记零。包内提供可复用接线，App 不按厂商重写上传和引用映射流程。

### 5.4 会话与不透明状态

将 response／interaction ID、签名推理块及厂商必要状态封装为带协议、模型、会话和身份作用域的 continuation。对 App 提供统一持有、序列化和恢复方式，不要求业务理解原始结构。状态不包含凭据，不进入普通文本日志或模型可见 prompt，不跨账号或不兼容端点回放。

客户端完整历史和厂商服务端续接是明确的两种上下文策略。Runner 在同一上下文计划中记录实际采用的策略，避免历史重复发送与状态重复计入。远端不可见上下文的 token 不能伪装成已精确测量；仅使用有依据的估算／上游用量，并明确可执行的限额保证。切换协议时使用可移植历史重建；无法重建的签名或远端状态明确失效，不宣称任意时点无损热切换。

Core 定义 continuation 的封装、版本和作用域校验合同，Support 实现序列化、脱敏和协议回放；App 注入存储、保留期与当前身份端口。包内提供可复用接线和内存参考实现，不自带强制持久仓库或要求普通调用安装状态服务。

可见业务结果、受控 continuation 存储和宿主资源句柄分别管理。journal 只保存适合上下文使用的可序列化业务投影；连接、设备、流对象不进入 structuredClone 或持久快照。续接通过版本化受控封装／宿主端口保存，记录来源、作用域、过期和数据保留策略，导入时重新校验身份、协议和模型；可移植历史不足以重建时明确拒绝恢复。

所有新增事件与内容类型同步声明脱敏和 metadata 投影；即使开启内容诊断，也不能直接记录签名推理原文、媒体字节、带凭据 URL 或 continuation 载荷。默认不启用远端持久状态；显式选择服务端续接、后台或托管能力时告知其远端保留要求。协议强制的临时保留不能被 store:false 冒充禁止存储。

### 5.5 工具执行归属

本地工具始终先形成提案，再由现有 Core 工具执行链校验、授权和执行。并行提案不等于获准并行执行；复用既有执行约束，不在 Provider 中执行 App 工具。调用 ID、工具结果、文本与必要签名按协议顺序回传。

托管搜索、代码执行或远端 MCP 等能力由显式配置授予厂商侧访问，访问范围和凭据由宿主确定。适配器报告远端执行事件和产物来源，不把厂商内部工具活动计为 Core 已授权的本地调用。无法在本地权限合同下表达的能力不可默认启用。

### 5.6 任务、批量与实时生命周期

一次 submit／query／cancel／read 是 Core 调度的有界操作，Provider Support 执行一次协议动作。轮询等待策略作为可替换 Support handler，由现有 Core／Durable 驱动；wait 便捷入口仍走同一生命周期和账本，返回后不得留下隐式计时器、重试或继续执行权。

后台和批量由 Support 提供提交、轮询／订阅与结果收集接线，但所有模型消费经 Runner 的身份、取消、预算和诊断边界。提交前扣除调用尝试，轮询次数与模型调用次数分别记录；网络重试不能无依据再次提交计费任务。远端任务 ID 与状态可经宿主存储恢复，凭据重新注入；取消请求、远端确认取消和已完成分别表达。复用甲计划已有 Durable／等待机制，不新增独立持久调度器。

operation、batch item、实时 connection 和 generation 采用不同执行身份及状态。提交成功和连接打开只表示已接纳，不写普通生成完成回执；只有明确生成终态才能提交对应成果。查询回传已有完成成果时按 operation／item 身份去重，不再次触发工具或计为新生成。

提交前保存稳定 operation ID、请求指纹及资源预留；适配器声明幂等键或按客户端 ID 查询能力。提交结果未知时先对账，不自动重新提交；没有远端 ID 或可验证幂等手段时保留 unknown 并提供宿主接管路径。持久恢复由宿主提供排他存储与当前授权，跨进程准入额度须借甲计划的持久预留保证；不能仅重建请求内账本便重置额度。远端任务 ID、续接 ID 和 Batch item 关联分别保存。查询、读取产物、取消与继续分别检查当前身份／权限。原执行期限或额度耗尽后允许独立有界的只读终态查询及清理，不能借此新增生成。句柄过期、远端不存在和不可查询分别报告，不从头执行。

取消控制请求使用独立有界 cleanup lifetime，不复用已经 aborted 的 signal；本地停止接纳、远端取消请求、远端确认和未知结果分别记录。迟到可见输出不进入业务成果，迟到用量、终态及远端执行事实进入受控对账。取消本地等待不等于远端取消成功，不保证停止计费，也不撤销已经发生的远端或本地副作用。

实时采用独立的可选 Core 会话合同，共用预算、工具和事件语义。会话打开、每轮生成与媒体输入分别计量；连接时长、音视频量和上游 token 不混成文本字符数。输入排队与背压有界，打断废弃旧输出，迟到事件按 generation ID 隔离，重连不自动重放有副作用操作。浏览器媒体由 App 提供端口；短期连接凭据由 Support 接线，长期密钥不暴露到客户端。关闭及取消释放连接、队列和媒体资源。每次本地工具执行重新检查当前身份及权限；登出、改密或撤权后旧会话／重连不恢复授权。打断使未准入的旧生成提案失效；已准入或已执行操作按现有副作用合同完成对账、记录和迟到隔离，不能把丢弃音频等同于撤销操作。

### 5.7 计量与可强制保证

调用准入、可测输入、媒体量、远端报告用量与费用分开记录。输入计量附 measured／estimated／unknown、计量范围与计量器版本；精确范围须对应冻结后的实际请求及可见状态。不可见远端历史、媒体或厂商内部循环没有可靠依据时不填精确 token，不把未知用量填零。请求要求严格上下文容量或费用硬上限，而该执行形态不能强制保证时，在提交前拒绝，或由宿主显式改选可执行的限制合同。

普通调用尝试、每次远端生成、批量逐项预留／消费、实时会话时长与轮次分别定义；Batch 不是仅占一次普通调用额度。提交前预留、终态对账、重复事件去重和资源释放遵守同一账本；轮询／查询独立限流，不伪装模型消费。已准入失败／拒答／取消保留尝试与已知用量。托管工具和远端 Agent 内部工作仅在上游提供可执行约束时承诺硬限制，usage 回报不是实时计费闸门。

## 6. 修改范围和兼容策略

优先修改 src/structs/model、src/model、src/support/model、公开入口与相应开发资料；确有复用组织收益才增加 src/kits 模块。更新上下文、journal、诊断或预算的必要部分，但保持 Engine 的工具授权、状态提交和路由语义。

保留现有 CompatibleModelProvider、普通文本调用、原生／JSON interaction 和 session 用法的可用路径。实现采用单一内部模型与局部桥接，不维持两代 Runner。确实无法兼容的类型变化需列出迁移清单，同步仓内消费者；不能只以文档声称兼容。乙计划不要求更改已发布包身份、npm 名称或消费方 import。

P0 固定现有入口及消费者基线：普通文本、native／JSON 单选择、session 多调用、自定义 ChatProvider、动态配置与配置快照，以及 Server／Banker 的 Provider 继承、transport 装配、历史和诊断接入。按“配置／接线变动”和“业务逻辑变动”分类记录迁移；后者逐项解释为何不能由包内吸收。自定义 Provider 无需登记官方厂商目录，旧 Provider 经局部桥接接入统一完成合同；原 stream-only Provider 的自然结束仅沿用旧有限流保证，不伪造上游明确终态证明，要求严格完成证明的调用在缺能力时拒绝。最简对象、原型方法／receiver、自定义 transport 及现有继承构造入口均有回归；不能无依据推定其具有所有新能力。

每个新增 Core 机制记录：现有契约缺口、唯一所有者、最小公共 API、失败语义及维护成本。现有 Support 足以承载的差异不升级为内核必填字段。

## 8. 验收矩阵

维护一个公开示例，同一业务工具目录和 handler 通过配置运行各协议的承诺格。至少覆盖文本助手、多模态输入、JSON 选择、严格结构化、单选择和文本与多调用混合的 Agent 循环；另设统一后台、批量和实时示例。不能只测试请求字段映射。

- 协议：完整返回、碎片／交错工具参数、usage、终态、拒答、截断、空结果、未知必需事件、错误、超时和中途断流。
- 状态：两轮以上工具往返；签名／推理／续接状态保真；历史不重复；切换协议、模型及账号的隔离拒绝。
- 工具：零／一／多调用、文本混合、未知工具、坏参数、授权拒绝、结果关联、托管工具归属；任何厂商路径不能绕过本地授权。
- 生命周期：上游接受后取得远端 ID 前断线、提交结果未知、恢复查询、重复查询、取消竞态、批量部分失败；实时打断、背压、迟到、重连和关闭后资源释放。
- 预算：提交重试、后台轮询、真实用量、不可见远端上下文及媒体分别核算；本地能力／权限／预算预检拒绝不发生成请求；已准入尝试不回滚，上游拒答／失败／取消照实记录用量，未知不能记零。
- 内容与输入资源：混合内容及工具关联的顺序保真；音频／视频／文件按方向验证；资源解析／上传的取消、大小限额、权限、失败不生成及准备成本记录。
- schema 与隐私：可移植定义复用、不可映射约束定位、wire name 碰撞；不可序列化资源隔离；新增内容事件和 continuation 不泄漏到诊断。
- 实时授权：撤权后迟到提案无新副作用；中断前已执行操作可追溯；重连不能恢复旧权限。
- 接入一致性：同类任务切换协议只改声明和必要参数；不新增业务端厂商判断；自定义 Provider 仍可实现公共契约；可选端口经过 settings／binding／child 后仍可用，receiver 和私有状态保留。

按仓库检查标准选择必要定向验证，不因文档设计运行完整构建或真实模型调用。正式实现分别记录类型检查、确定性协议 fixture、模拟服务和真实服务结果；fixture 成功不能替代真实模型或实时媒体验收。每个承诺格以同一参考样例、相同业务代码给出配置差异及结果读取对照。声明映射通过、模拟协议通过和真实服务通过分列；真实服务未验证的承诺格保持未完成，不以不支持拒绝代替适配器交付。

P4 对五类会话协议（Chat Completions、Responses、Messages、generateContent、Interactions）分别给出真实服务 smoke，至少包含文本与本地工具两轮往返，记录端点、模型、协议版本和日期。smoke 是最低门槛，不代替每个承诺格的专项证据；缺凭据或上游受阻保持相应项未完成，不能降格为模拟通过。

P4 从最终候选 tarball 在仓外干净消费项目安装，验证实际声明的公开导入路径、类型声明、依赖完整性及必要公开示例；ESM／CommonJS 按包实际声明验证，不新增未承诺运行环境。消费项目不得依赖 workspace 源码、私有路径、软链或隐式依赖。源码入口核对、pack dry-run 和成功打包均不能代替此安装验证；本项不包含 npm 发布。只在源码或包体发生相关变化时重做必要验证。

真实外部调用在具备授权、凭据和费用边界后执行；没有证据的协议能力标为未验证。
