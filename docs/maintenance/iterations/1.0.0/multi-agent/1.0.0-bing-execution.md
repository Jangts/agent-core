# 丙方案实施与验收记录

日期：2026-11-25。用户在七方审计与说服对齐后明确授权按子 Agent 落地。范围是结果评审、已有结果选择、等待裁决接线、两端专业 work 消费者和配套资料；不代表整个 1.0.0 完成或发布。

## 任务组织与合同决定

| 负责方 | 独占工作 | 依赖与收口 |
| --- | --- | --- |
| bing_contract | ResultReview 合同、检测／复核／准入、类型与语义评估 | 先给最小签名，再实现；不改共享出口或消费者 |
| bing_probe | 五进程 P0、ReviewDecision、ReviewChoice、同故障接线对照 | 复用 Waiting/Durable；App 仍提供真实原子存储，不新增内核调度 |
| bing_consumers | 两端 work 接线、答复协议、真实服务回归与业务文档 | 保留旧 checkpoint 身份、额度与生命周期；不扩展到 UI 或聊天工具 |
| 主审 | 共享出口、集成、源码复核、包体及文档站来源、验收边界 | 保留既有乙丁及其他暂存修改；按依赖统一编译，避免多人写 barrel/package.json |

实施顺序调整为小可乐首消费者、Banker 第二消费者：小可乐已有两路分析，能先以真实路径验证闭环；Banker 再接双专业委派。两端仍都交付，不改变计划范围。先以既有 Kit 完成 P0，再抽取实际重复的身份、覆盖、答案及回执校验。公开职责分别为结果评审、裁决关联和有界结果选择，不提供全能团队或共识引擎。

## 实际行为

- `result-review` 支持声明检测器、可信 scope／输入引用、独立 findings/coverage、有界复核及无进展出口；确定性检测不调用模型，语义处理用调用方当前 Runner。宿主 blocking 策略可以覆盖模型字段，准入默认阻止未完成必需检查及未解决阻塞项。
- `review-decision` 绑定父任务、争议内容修订、资料与策略版本、等待身份、submission 与动作 ID；首次接纳检查原期限，纯查询不推进，已接纳回执可幂等查询。宿主仍负责原子比较接纳，取消不等于回滚。
- `review-choice` 收拢两个 App 原先完全重复的比较、持久形状验证、答案、等待及回执接线。配方接受一至两个完整已有摘要；多结果场景可独立使用通用 ResultReview。App 只保留业务投影、内容 hash、可信身份、资料核验及锁/CAS。
- 两端 `respond` 只接收答复，`resume` 才选择已有结果。readonly checkpoint 完成不等于结果已接纳；等待或缺覆盖时拒绝 Family 成果导入。新 review 是原 work 的可选附属数据，无 review 的历史记录沿原合同读取。记录仍为七天保留、创建后 24 小时执行期限、每次八调用保守预留、跨尝试最多十六调用。
- 跨等待选择现有结果不再调用模型，因此直接继承原 checkpoint 的累计保守预留，不为新任务初始化另一份满额额度。若将来确需后续模型阶段，须另行完成父级原子分配合同，当前消费者不声称已支持该分配器。

## P0 与独立复查

五个新进程实际贯通：保存两个只读意见与争议→幂等答复→保存动作后响应丢失→纯查询→只读对账。父消费 3/3，模拟动作写一次，执行尝试一次，期限不变。普通 handler 与推荐接线在同一原子端口和相同响应丢失故障下都不重复执行；推荐接线集中前置关联、期限和回执校验。该探路不证明断电持久性、陈旧文件锁恢复或外部系统 exactly-once。

实现后由原作者交叉只读复查，实际发现并修复：

| 发现 | 修复和验证要求 |
| --- | --- |
| sourceVersions 插入顺序不同导致合法裁决误拒 | 规范结构比较，不以 JSON 键序作身份；非排序来源回归 |
| 接纳后入口拒绝相同答复重试 | 保留同 waitId 的幂等重试，交 Waiting 校验 submission 与答案 |
| 小可乐子集分析被当成完整可选结果 | 两个独立成员各读完整资料，测试核对两个输入的全量资料覆盖 |
| Banker 超长完整报告截断后仍标完整 | 正式报告超限标 incomplete，保留有界诊断而非截断后放行；不能人工绕过 |
| Banker 委派 catch 丢失原失败原因 | 既有诊断链记录安全的错误分类、堆栈与 cause，超限含允许值及实际值 |
| 通用准入接受 `skipped: ''` 的畸形覆盖 | 入口共享严格 scope、findings、coverage 与引用数组验证，畸形记录拒绝 |
| gate.read 中取消后仍能进入 accept | 接纳前再次检查取消；已发出的 accept 仍须 settle，新增两种取消回归 |
| 已接纳纯查询未验证等待提交关联 | 核验 gate/submission 与回执一致，不触发 accept 或额度分配 |

## 验证证据与边界

本机默认 Node 14 不满足要求，主审使用已有 Node 24.22.3；消费者另以已有 Node 22.20 做定向验证。未安装或替换全局运行时。

首轮 SDK 四文件 16/16；新增配方与关联专项 11/11，二者有重叠，不相加为唯一用例数。两端类型检查通过；消费者六项覆盖真实 WorkService、ModelRunner、两成员、主动比较、等待／不完整／接纳、原预算不变及 Family 准入。Banker 路径保留真实专业委派、product.read 前置工具和证据 ID 校验，仅替换外部 Provider/config/存储端口。交叉复查修复后的最终定向结果在本节后续补记，不以首轮结果代替复查。

真实模型语义评估：冻结 `bing-review-input-v1` 与 `bing-review-prompt-v1`，十四个合成原始意见覆盖同义、直接矛盾、隐含时间、不同条件、资料版本、同源错误与恶意材料，每类两例。阈值预先固定为召回及特异性 ≥0.85、未完成误放行为零；候选生成不读标签。`deepseek-flash` 有效运行十四调用、已报告 7184 tokens，候选召回、语义召回／特异性、端到端召回／特异性均为 1，未完成及误放行为零。

首次真实运行在完成样例后因测试 harness 从未绑定 Runner 根读取 totalCallCount 而失败，未输出报告、未完成质量断言；不是模型质量失败，也不记零费用。修复为同一已绑定执行和额度后，增加十四次共享预算及第十五次本地拒绝回归，再运行上述有效十四例。两轮共二十八次样例调用；仅第二轮有完整指标与用量证据。

这些结果只证明 SDK 测试语义处理器在冻结样本、提示词与配置下的行为，不等于两端业务中文提示已逐例网络验收，也不证明开放场景完备性、真实业务事实正确性或广泛抗注入。证据级事实核实、跨任务隐藏依赖发现、任意子任务恢复、后台调度、聊天/UI 裁决入口均不在本次已交付范围。两端实际比较的是完整已有摘要，不能把 reason 当外部事实核验。
