## 可选调用级答复指导

新增公共类型ReplyGuidance，只含defaultDetail: brief / normal / detailed；ModelPrepareRequest及ModelCallRequest接受replyGuidance，PreparedModelCall暴露冻结值。Support.resolveReplyGuidance和ReplyGuidanceSources从既有App登记选择的值归并：defaults < node < tools < call。工具冲突要求明确call，不靠顺序；覆盖前的值也验证，不接受任意指令字符串。

Core在交互准备时生成固定短指令，和交互instruction一起冻结。prepared.measure与invoke走同一计量/发送路径；modelOptions重准备不重复注入；已prepared调用再附指导会拒绝。Engine节点prepare/invoke两处均透传。默认关闭、不自动扫描任意节点或工具，不提升用户/工具原文为system，不自动施加到内部推理调用。

简短默认要求先给结论和必要支撑、摘要压缩原文；用户明确提出详情、全量、语言、风格和格式时仍遵从，保留影响判断的限制及协议必需字段。它不硬截断、不做关键词分流、不增加隐藏复审调用或行动授权。语气/受众/具体参考仍通过可信任务上下文配置。新增指令占用既有交互/schema字符额度及总输入/token；不宣称零成本、确定缩短、速度提升或省钱比例。

## 定向审查及处置

沿用原八角色设计审计，实施增量只作相关角色回查：

- R3发现Engine逐字段映射漏透传，以及Object.hasOwn会对非字符串detail强制转换。已修复invoke/prepare双映射和typeof检查，新回归覆盖两项；R3确认无剩余具体阻断，并确认canonical文章中的预算/准备保证没有夸大。
- R6确认短指导从实际输入入手、可选启用、用户明确要求和协议保留、效果边界准确，无具体反对；只确认文档/体验，不代替运行。
- R4以前向“全模型自由答复+原文参考稿+真模型/UI未执行”走读Skill，并实际执行4个纯JSON反例：不误报全模型，不因extracted内容存在升级证据，冒领/零断言不能支持pass，opaque receipt仍未核实。诊断里将semantic零断言误写offline的提示已改为实际phase。

没有未对齐的A/B取舍，未投票；没有把这三份定向确认写成八方重新全文验收。
