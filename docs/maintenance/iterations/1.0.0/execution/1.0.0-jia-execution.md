## 2. MockGPT 与确定性验证

新增原生组合用例通过真实 CompatibleModelProvider 接入 `mock.fetch`，不启动 HTTP 服务、不访问模型网络。覆盖父子共同计账、工具授权拒绝、修复不重做保存、HTTP 429 失败计账、取消子生成及非合作外部保存的晚到结果隔离。

新等待与聚合用例还核对：重复／过期／旧代次／跨主体答复，当前授权撤销，保存确认丢失，JSON getter 不执行，父结果冲突、部分成果及共享最后一次额度。确定性脚本不构成真实语义理解、抗注入或模型修复质量证明。

首轮 ESM／CommonJS 编译通过。以下为首轮历史证据，不能代替七方复审修复后的重新验收。使用 Node 22.23.5 对 `packages/agent-core/test/*.test.mjs` 的 133 个文件执行回归：**1054 项，1051 通过、0 失败、3 跳过**。三个跳过项为显式开启的真实模型用例，默认回归不读私有凭据或发模型网络请求。

事件去重修复曾触发一轮新增断言失败：Engine 的构造时方法包装改变对象身份，简单比较 observer 引用不足。最终采用内部包装身份追溯，保留快照与 receiver；新增测试中一次错误使用 WorkflowModel 的字符串短调用也已改为具名输入。上述问题修正后才取得最终零失败结果。

## 3. 同 key／异 key 多 Runner 实测

使用 Cafe 服务端与 Banker 已有本机配置，密钥只在进程内读取，从未输出、写入本记录、测试结果或源码。两份 key 实际不同，配置的服务入口与模型相同，模型标识为 `deepseek-flash`。

三组依次执行，每组并发两个独立 Runner，每个仅允许一次调用、输出上限 128 tokens。只发送合成标识请求，不发送用户资料、业务上下文或真实工具操作。总计 **6 次真实网络请求**，不自动重试；后续预算拒绝均发生在本地，没有产生额外网络请求。

| 组 | 请求／成功 | 凭据与响应隔离 | 独立预算 |
| --- | --- | --- | --- |
| Cafe 同 key 两个 Runner | 2／2 | Authorization 与对应配置匹配，返回各自标识 | 每个消费 1；各自第二次调用在 Provider 前拒绝 |
| Banker 同 key 两个 Runner | 2／2 | 同上 | 同上 |
| Cafe／Banker 异 key 两个 Runner | 2／2 | 两个不同 key 各自发送，标识未串用 | 同上 |

**本次可支持的结论**：相同 key 不会令两个独立 Runner 自动共享账本，也未导致本轮串用响应；异 key 不会改变 Core 的本地预算规则。只有实际父子账本关联才共享额度，不能以 key 或同一个配置对象推断共享。

本小样本未触发服务端限流，三组成功率无观察差异。它不证明同 key／异 key 的容量、服务端配额是否独立、计费账户隔离或长期速度差异；未在开发机压测或以耗时推断性能。

已补充可复用的 `test/multi-runner-live.test.mjs`，仅 `AGENT_CORE_LIVE_TEST=1` 时读取显式配置并发请求，默认跳过。实际六请求由隔离验证脚本完成；为避免重复费用，没有再开启该测试文件额外重复六次网络调用。新文件的默认跳过行为已纳入最终包内回归。

## 5. 决策与边界

1. 保持 Core 微内核：不建任意图持久引擎、调用栈恢复、分布式调度或统一 harness 类。持久顺序、等待和聚合是可选 Kit，App 显式组织；既有 Support 接线继续可替换。
2. 不执行 v3 checkpoint 方案：新提交写可选 v2 commitId，旧记录无需拥有该字段。不是双内核运行或自动历史重放。旧 reconcile 的未标记 State 返回改为显式三态，公开类型与案例同步。
3. 外部 LangChain 内部调用实测未进入 Core 账本，独立局部 cap 生效；未验证暂停透传，不宣称无损融合。普通 wrapper 足够，未增加产品 adapter 或必需运行依赖。
4. 进程重新进入与真实磁盘／机器崩溃分开。参考文件存储不处理陈旧锁恢复，不证明断电持久性、分布式一致性或 exactly-once。
5. 取消可隔离迟到结果，但不撤销已发生或仍可能发生的外部副作用；需要当前授权、幂等或稳定对账事实。等待 ID 不复用由 App 保证，不保存无限历史清单。
6. 真实模型仅证明本次六个小请求的凭据／响应／本地额度边界，不代表复杂任务、工具选择、压缩或语义质量已全面验收。

本地甲计划交付已完成并可交 1.0.0 整体验收；其他版本任务、生产服务、真实用户数据、发布和部署均不在完成声明内。未执行 Git 提交、推送、npm 发布或部署；已有工作区改动保留。临时模型输入输出、隔离依赖和测试运行时在记录必要结论后清理，不作为交付物。


## 6. 七方复审：总覆盖方的遗漏修复

总覆盖审查发现 A3 的“同任务普通 handler 与推荐接线对照”此前只有要求，没有实际配对例程，首轮全勾选缺少这一项证据。现补[普通 handler 对照](../../../../../packages/agent-core/development/examples/harness-handler-comparison.md)与独立回归：两种写法正常交付、Provider 序列、四次共享额度、额外调用本地拒绝、拒权无保存／修复均一致。Node22 对此新增回归 1／1 通过，不构成整个修复后测试集通过。

对照明确保留普通函数在固定小任务中的简洁性；图的收益在于节点转移、状态接纳和错误定位，不把 Core 预算／授权重复算作图语法优势。取消、诊断、持久和并行仍用专门案例，不声称此对照证明所有故障等价。

新增例程的包白名单、索引和修复后全量结果由主线程统一整合。P4 在本轮重新验收前保持打开；首轮关于源稿／包体／消费者的通过不能代替当前产物验证。
