## 2. 本地静态基线

以下路径相对包根，记录 T3 研究时的工作区基线，包含当时未提交修改。它不是后续实施后的现行合同；最新实现及重新验证见文末复审说明。

- `src/structs/execution/workflow.ts`：普通节点 `run(state, context)` 返回部分状态，路由决定后继。`WorkflowContext` 提供 model、tools、signal 和诊断；不是直接消费 LangChain Runnable 的接口。
- `src/execution/engine.ts`：handler 完成并检查取消后提交补丁，再选路由。原 state 进入 handler，类型上的 Readonly 不保证深层隔离；提交补丁也不是外部存储事务。
- `src/model/runner.ts`：绑定的 Runner 持有请求账本；`createChildBound` 通过 `this.budget.child(...)` 派生账本，并共享 requestGate。`bind` 对未绑定模板按 execution 对象建立请求状态，对已绑定 Runner 返回自身。
- `src/model/call-budget.ts`：同步父子扣减解决请求内竞争，不自动形成跨进程持久账本。
- `src/execution/engine.ts` 的 `bindModelRuntime`／`runnerFor`：外部 runtime 以真实 getter 和调用委托接入；内部配置模型路径通过 `parentModelBudget` 连接本次 Workflow 账本。两个路径不能混同。
- `src/kits/durable.ts` 与 `src/structs/kits/durable.ts`：已有排他存储、顺序游标、尝试及保守模型额度预留、safe／reconcile 和定义修订校验；不是任意图恢复。T3 当时的 reconcile 返回完整 State 后推进步骤，未知结果不能靠返回一个未改变状态来表示。

## 3. 采纳决定与最小方案

本节的“采用／改写”是下一阶段设计选择，不是完成标记。已有接口能满足时交付组合与证据，不为研究成果新建 API。

### C01 采用：完整 Agent 作为普通节点内部的有界执行体

U1 的合同是：`createAgent` 产生的执行体可置入 LangGraph，内部 middleware 随之执行。这说明应保留子 Agent 的完整循环与钩子；**不证明该对象能直接传给 Core 的节点注册**。[官方示例](https://docs.langchain.com/oss/javascript/langchain/middleware/overview#use-middleware-inside-a-langgraph-workflow)

本地最小方案是普通节点调用原生子 Agent：挑选父输入 → 运行子 Agent → 校验成果 → 返回允许的父状态补丁。工具与上下文保留在子执行内部；父流程不把子结果当授权、预算或任务成功事实。不新增专用 AgentNode 类型或平行调度。

所属：App 普通 handler，稳定元数据接线可归 Support；Core 仅处理已有调用边界。

可证伪验收：子 Agent 至少经历模型、工具、后续模型的有界循环；父节点只做映射与接纳。若示例只是单次模型函数，不能证明“完整 Agent”。子失败后父结果不能显示成功，修复输出格式不能重做已确认工具写入。

### C02 改写：按状态映射组合，不照搬共享通道模型

U2 区分共享字段的直接子图与不同结构的包装函数；后者明确映射输入输出。采用其接口隔离思路，优先独立子状态和白名单补丁，不因两边字段同名就共享父对象。[官方通信方式](https://docs.langchain.com/oss/javascript/langgraph/use-subgraphs#define-subgraph-communication)

直接将 LangChain Agent 当作 Core 节点目前**不满足公开合同**：Core 需要节点 id、description、routes 与 run；invoke／stream 执行体不是该节点定义。普通 wrapper 是合同上可行的接入候选，真实包可运行性仍未验证。不能用类型断言或伪对象关闭 D2。

所属：App／可选 Support。接入存在可复用的安全接线负担、普通 wrapper 不足且有独立通用价值时，才考虑通用 adapter；不以已有多个业务消费者为前提。

可证伪验收：子状态含私有消息与敏感字段时，父只接纳声明结果；子修改自身输入不改变父状态。真实包阶段分别记录直接方式不成立的原因与 wrapper 的保证，不把 LangGraph 内部直接子图支持当作 Core 互操作证据。

### C03 不采纳异常式中断；改写为显式等待身份与步骤边界

U3 明确：函数调用的子图中断恢复时，父调用节点和子图的中断节点都会从头重入。恢复不是 JS 调用栈续接。[官方重入说明](https://docs.langchain.com/oss/javascript/langgraph/interrupts#using-with-subgraphs-called-as-functions)

U7 固定源码可确认 interrupt 要求运行配置与 checkpointer，以 scratchpad 计数选择 resume 值，无可消费值时抛 GraphInterrupt。该局部实现不证明全部恢复正确性，也不是已复现的上游缺陷。[固定实现](https://github.com/langchain-ai/langgraphjs/blob/61aad39ef67051aa04cacd57b75a60538c5fd72d/libs/langgraph-core/src/interrupt.ts#L89-L155)

Core 不复制这套异常与位置索引协议。R2 先在 Durable 步骤／节点边界记录具体等待、执行代次和结果，继续时重新绑定身份与权限。App 提供原子答复消费；可复用接线避免每个 App 自己猜测代次。没有持久等待记录时不声明跨重启暂停。

可证伪验收：确认前写入已完成、确认后重启时不能再次写入；同一旧答复不得消费下一次等待；重复和冲突答复分别返回确定结果。不支持外部子 Agent 暂停透传时应拒绝自动恢复，不能把重新 invoke 叫继续。

### C04 采用故障断言；改写副作用恢复，不默认增加节点自动重试

U4 区分图状态边界与外部写入：重试可重新执行节点；操作身份须在执行前可恢复，确认丢失视为未知。采用这些失败断言，不将网络异常或可重试错误分类等同于业务操作可重放。[官方副作用边界](https://docs.langchain.com/oss/javascript/langgraph/fault-tolerance#retry-boundaries-and-idempotency)

本地优先补齐 Durable 的已完成／确认未发生／仍未知表达与耗尽后的确认路径。safe 只适用于能证明安全重放的步骤；未知状态不能推进游标。执行身份、操作身份、调用尝试身份分别记录，App 对账与外部幂等保证不能由框架凭空补齐。

最小方案是局部 Kit 合同加真实端口；不为此在 Engine 再建另一套 durable 重试状态机。不因上游支持退避或超时配置就逐项追平。

可证伪验收：外部已成功而本地确认丢失后，先查询或对账；仍未知时保持未知及保守预留，不盲重发、补偿或推进。授权撤销后不得执行新操作；无模型只读查询不应被执行额度误挡。

### C05 改写：独立分支结果加显式汇合，暂不建设通用 reducer 引擎

U5 说明每字段 reducer 控制更新，缺省更新替换旧值；这是一种共享状态模型，不代表对任意非交换业务更新自动给出正确结果。[官方 reducer 合同](https://docs.langchain.com/oss/javascript/langgraph/graph-api-state#process-state-updates-with-reducers)

R3 的更小方案：各分支收到独立输入，返回带稳定分支身份的结果集合；父按声明顺序显式检查和接纳，冲突默认拒绝。聚合算法可在普通 handler／Kit，不要求所有字段注册 reducer。数据 fork／Family 合并不当作并发调度。

可证伪验收：交换完成顺序，结果或拒绝原因仍一致；分支不能直接修改父状态；父保存失败不宣布汇合完成；保留的成功成果可回查且不会被下一代运行误收。并发共享额度另按下一节验证。

### C06 采用持久职责区分；不将内存样例当跨进程证明

U6 区分执行 checkpoint 与跨运行资料存储，并说明内存 saver 不跨进程保存。采用该区分，不引入默认数据库或记忆服务。[官方存储边界](https://docs.langchain.com/oss/javascript/langgraph/persistence)

本地 Engine checkpoint 仍是宿主数据／分支身份，不据此升级为恢复游标。R2 用已有 Durable 和宿主临时持久端口证明最小可恢复单元；接线不足才提出新契约。状态、后继位置与必要回执引用的原子关联由真实存储端口保证。

可证伪验收：新进程恢复、两个恢复者竞争、存储成功但返回异常时读回确认，均能解释下一合法动作。内存对象恢复只能证明序列化和局部逻辑，不能替代这些证据。

## 4. 原生组合的反方检查：防止伪共享预算

这是由静态调用路径提出的风险与验收要求，尚未运行示例或故障复现。

| 接线 | 能由源码支持的结论 | 不能据此声称的结论 |
| --- | --- | --- |
| 已绑定父 Runner 的 `createChild` | 子账本关联父账本，并共享 requestGate；子信号组合父生命周期 | 自动成为跨进程持久额度，或与任意新 Engine 账本共享 |
| `new ModelRunner` 使用同 Provider／maxCalls／诊断 runId | 配置和诊断可相同 | 账本共享；相同数字和标识不建立对象关联 |
| 复用未绑定 Runner 模板，但使用不同 execution 对象 bind | 每个绑定可有独立请求账本 | 父子预算累计，或跨请求累计 |
| Engine 配置模型 | runnerFor 通过 parentModelBudget 关联本次 Workflow 账本 | 嵌套的另一个 Engine 自动加入该账本 |
| Engine `bindModelRuntime` | 调用与计数委托给选定 runtime | Engine 的新 maxModelCalls 账本自动约束该 runtime；runnerFor 的此路径直接返回 runtime |
| Durable 步骤 context 的 maxModelCalls | 告知本次持久预留额度上限 | handler 任意私建 Runner／Provider 调用都会被 Kit 自动拦截 |

因此，R1 应先用一个请求绑定的父 Runner 派生子 Runner，再把真实子 runtime 接给子 Agent；父图也使用同祖先的真实 runtime。若直接委托 context.model.invoke，只能声明共用受控调用入口；需要子局部限额时仍须有实际约束机制。WorkflowContext.model 当前不公开 createChild，不应在示例里假装该方法已存在或通过私有字段取账本。

下一阶段必须观察 Provider 实际进入次数及父子计数，不能只断言配置中的 limit。最小反例为：父先消费一次，子至少需要两次，父总额度设为两次；第三次 Provider 进入必须被挡。另测两个兄弟争最后一次、失败调用计账、父预留、取消后新调用、独立请求不串账。若绑定 runtime 的权威额度与 Engine 配置额度不同，示例明确由谁约束，禁止展示一个不起作用的数字当总限制。

外部 LangChain 内部模型未接 Core 时，采用独立有界资源域。父一次节点调用不等于子一次模型调用。若连外部硬限额都未验证，只能记为边界未满足，不能靠文档声明完成。

## 5. 下一阶段任务与停止条件

| 任务 | 最小产物 | 可证伪关闭条件 |
| --- | --- | --- |
| N1 原生 R1 接线 | 公开入口的普通父节点＋完整子 Agent；父请求 Runner 派生子 Runner，显式状态映射 | Provider 进入次数与真实父子账本一致；拒绝无副作用；取消不接纳迟到补丁；不通过私有接口接线 |
| N2 Durable 缺口 | 先写三态对账、额度耗尽后只读确认、终态查询的合同与案例 | 未知不推进；新进程不退还未知额度；查询不触发新执行；再据不足决定 Kit／Core 最小修改 |
| N3 等待与 R3 | 显式等待消费；独立分支结果与父接纳 | 旧答复、旧代次结果和冲突稳定拒绝；完成顺序不影响约定结果；不另建通用调度 |
| N4 LangChain 最小原型 | 后续锁定实际依赖及确定性 Provider，普通 wrapper；本批仅合同候选 | 真实 Agent、middleware 和工具均运行；错误、取消、事件和限额有证据；暂停不支持时明确拒绝恢复 |
| N5 Support／Skills 收敛 | 从 N1—N3 提取真实重复元数据／代次／受控入口接线，原地增强使用与排障方法 | 比普通 handler 少维护重复安全规则，删掉辅助后公开接口仍能替代；无重复就不凑 adapter 或新 Skill |

反方保留意见：参考任务须先给目标行为和故障断言，再选 API；不能反过来为拟增加的接口构造唯一成功场景。若普通包装、现有 Durable 和结果集合已经满足边界，本轮研究应以组合、回归与指导收敛，不再追加通用图恢复或 reducer 产品。

本批 T3 完成的是来源固定、契约对照、采纳选择与后续断言。R1—R3、真实包互操作、持久恢复及预算竞态均未在本批执行验证。

## 6. 七方复审的现行对照

上述 T3 研究是实施前记录，不能把“尚未运行”“reconcile 返回 State”等历史表述当作当前缺口。后续 Durable 已实现显式 completed／not-executed／unknown、确认优先及可选 v2 commitId；等待和聚合已分别落地。以现行源码及对应回归为准，不据旧文档重复建设。

D2 的早期临时原型虽已清理，本轮已用真实固定版本包补入可复用的显式开启回归，五场景通过，见[真实包复验](1.0.0-jia-langchain-probe.md#8-七方复审复现性补齐)。它仍不证明外部暂停透传、stream事件、共享账本或生产兼容。上游 commit 与网页查阅日期仍为原批来源，不声称本轮重新抓取并验证所有滚动网页。
