# 1.0.0 甲计划：真实 LangChain 包装节点可行性验证

日期：2026-11-25。关联[甲计划](1.0.0-plan-jia.md) D2 及[上游机制采纳记录](1.0.0-jia-upstream-decisions.md)。本记录说明历史确定性原型及本轮可复用真实包回归的证据边界，不是公开兼容承诺或生产 adapter。

## 1. 结论

真实 `createAgent` 可以通过 Core 普通 Workflow 节点调用 `agent.invoke`，保留其内部模型循环、真实工具及 middleware。原型证明输入映射、输出白名单、失败传播、父取消后的不提交，以及外部顺序循环的独立调用上限。无需增加 Core AgentNode 类型或产品级 adapter。

**没有自动共享 Core 模型账本。** 正常场景外部模型实际进入两次，Core Runner 累计消费为零。父图一次外部节点调用不能计为一次模型调用，更不能声称总费用已经统一约束。当前采用独立有界资源域。

未验证 stream 事件映射、共享预算、并行内部调用、暂停透传、持久恢复、模型语义、真实服务费用或生产吞吐。不能据本原型宣布 LangGraph／LangChain 与 Core 可无损融合。

## 3. 先读取的真实合同

安装目录内读取了以下文件，而非按旧 API 记忆拼装：

- `@langchain/core/dist/language_models/chat_models.d.ts`：BaseChatModel 的构造参数、bindTools、_llmType、_generate 合同。
- `@langchain/core/dist/outputs.d.ts` 与 `messages/ai.d.ts`：ChatResult 的 generations 与 AIMessage 的 tool_calls。
- `langchain/dist/index.d.ts`：createAgent、createMiddleware、tool 的真实导出。
- `langchain/dist/agents/middleware/types.d.ts` 及 `middleware.js`：beforeModel 在模型调用前执行及其返回方式。
- `langchain/dist/agents/ReactAgent.d.ts`：invoke 接收 messages 与运行 config，signal 和 recursionLimit 为调用配置，结果含消息及可能的其他状态。

这些是安装包内的类型和实现读取，不是跨版本保证。它们与[官方完整 Agent 进入图的说明](https://docs.langchain.com/oss/javascript/langchain/middleware/overview#use-middleware-inside-a-langgraph-workflow)方向一致；本批进一步运行的是跨到 Core 普通节点的包装路径。上游文档本身不证明 Core 接线自动成立。

## 4. 原型结构与复验规格

临时原型为 main `.tmp/langchain-probe/probe.mjs`，只用于本批实验。长期保留以下规格和实测结果，不把该路径当公开产品入口。

1. 自定义 BaseChatModel，bindTools 返回自身并记录绑定工具名；_generate 返回 ChatResult，没有外部请求。
2. 第一次模型调用校验输入为 `external:request-one`，返回 AIMessage，其中有真实 tool_calls：`read_receipt({ request: 'request-one' })`。
3. createAgent 的真实工具读取固定回执。第二次模型调用必须看到 human、ai、tool 三类消息，读取 ToolMessage 后输出 JSON。JSON 故意附带 identity、budget、privateMessages 等不可信字段。
4. createMiddleware.beforeModel 计数并在外部局部上限达到时拒绝下一调用。该上限限定本次新建、顺序执行的 Agent 请求，不宣称适用于未测试的并行调用或共享实例。
5. Core 普通节点显式构造 messages，调用真实 agent.invoke，传递 context.signal；校验最终 answer、receipt，只返回这两个字段。父 identity、budget 和初始请求保留，子消息与额外字段不进入父状态。
6. 父图绑定独立 Core Runner，其 Provider 若被误用会立即抛错。每个场景均断言其 totalCallCount 为零，避免将外部调用伪装成已共享记账。

Core 不能直接用该 Agent 对象替换节点定义：Core 节点要求 id、description、routes、run，而 LangChain invoke／stream 执行体是另一份合同。本批未做类型断言或伪对象“直接兼容”演示。可运行路径是普通函数包装；这与在 LangGraph 自身图中直接加入 Agent 的能力分别表述。

## 5. 实测结果

运行命令使用项目 Node：`node .tmp/langchain-probe/probe.mjs`，工作目录为 main。最终执行退出码 **0**；五场景全部断言通过。该命令是历史实验记录，临时目录清理后不作为维护入口。

| 场景 | 模型实际进入／返回 | beforeModel | 工具执行 | Core 消费 | 父状态与结果 |
| --- | --- | --- | --- | --- | --- |
| 正常 | 2／2 | 2 | 1 | 0 | answer=verified、receipt=receipt:request-one；仅接纳两白名单字段 |
| 第二次模型失败 | 2／1 | 2 | 1 | 0 | LOCAL_MODEL_FAILURE；不提交 answer／receipt |
| 工具失败 | 2／1 | 2 | 1 | 0 | 工具错误进入 ToolMessage；确定性模型识别其 error 状态并抛 TOOL_FAILURE_CONFIRMED；父不报成功 |
| 父取消、模型不合作晚到 | 2／2 | 2 | 1 | 0 | 父返回 PARENT_CANCELLED；释放阻塞后第二次模型仍实际返回，但父不提交结果 |
| 外部局部上限为 1 | 1／1 | 2 | 1 | 0 | 第二个 hook 抛 EXTERNAL_MODEL_LIMIT，模型未第二次进入；父不提交结果 |

所有场景父 identity 仍为 parent-owner，budget 仍为 1。正常消息序列第一次为 human，第二次为 human／ai／tool；绑定工具名确为 read_receipt。工具计数统计实际执行，不用工具 schema 数量替代。

工具失败场景的重要限制：这里**不是证明 LangChain 自动将所有工具错误作为整次 Agent 失败**。实际工具错误可成为消息供后续模型处理；本地确定性模型显式拒绝错误回执，保证该场景不会生成伪成功。这提示未来接入必须定义工具错误的任务成功语义和成果检查。

取消场景在第二次 _generate 已进入并等待门闩时触发父 signal，再释放门闩并观察模型实际返回。它证明停止父等待与迟到结果隔离；**不证明外部模型执行被撤销**。工具此前已执行一次，取消不回滚其事实。

## 6. 采纳与后续边界

采用普通 wrapper：状态结构明确、白名单返回、只传必要运行 config，可用真实包运行。暂不产品化 adapter，因为本批包装很小，尚未证明新增 API 能减少稳定重复接线或维护成本。Core 不导入外部运行时。

保留外部独立额度：本地 middleware 证明顺序循环的执行前限制有效；未来真实模型使用外部 runtime／Provider 的硬限额时仍须验证。要统一 Core 计账，必须让每次实际模型尝试经过同一受控调用入口，处理重试、并发、未知费用及取消；仅传相同 runId 或 maxCalls 无效。

暂不支持外部暂停自动恢复：本批无 checkpointer、Command、人工中断或恢复游标。外部暂停若无法映射执行身份、等待身份和副作用回执，父图不能靠重新 invoke 继续。持久存储、幂等和对账仍由明确的宿主端口提供。

下一阶段只在真实需求触发时增加：stream／父子事件归属、工具错误与完成检查的统一接线、可验证的外部硬限额、暂停／重启的安全子集。每项先写故障断言并用真实包验证，不将本原型扩展成兼容平台。
