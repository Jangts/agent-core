## 交叉复核发现与修正

1. C 初稿的“探索”只是固定阶段数组自增，不能解释业务单元与探索边界的选择。现以完整 explain-status 用例与依据服务状态/证据缺口推进的调查循环对照；在线不补读，异常状态读对应来源，无进展只尝试一次。补齐读取/生成/保存取消传播、未知写入回执查询失败保留答案、同范围授权、公开预算评估与格式修复不重开工具的断言。最终42项专属离线回归通过，未将确定性字段投影称作模型摘要。
2. D 首次只补 planning 前置读取，不足以验收主流程。现在实际注册从模块目录生成七类业务执行与结算节点，绑定所属工具、成果与恢复合同；保留基础能力的开放探索。成功回执先登记，成果加工只运行一次，明确 finish 且产生候选时直接进入公共交付守卫。不是逐工具铺节点或改变图的显示名冒充改造。四文件当前源码专项44项通过；同源名称补充7项通过。
3. Banker 预算把每次决策、可选复核、交付与故障恢复机械相加，可能因保守估计直接 partial。现在按当前必要工作评估，取消这个提前终止判断；内部高消耗调用仍显式计账，故障时保留程序自然交代。已有事实的一次调用交付有离线证据。
4. Banker Web 将非法配图进度、附属响应结构和运行摘要作为主回答的否决条件。现在隔离无效观察和每组附属数据；正文仍校验，缺少权威 done 或空正文不变成成功。非法附属值不进入 UI；附件缺口自然说明；不重复 POST。前端最终三文件23项通过。
5. 运行摘要保留14天而正文60天，原结果重放曾伪造零次调用摘要以携带消息身份。现在共享响应声明可选 run，独立 requestId 保留消息身份；服务端正常运行仍生成诊断，摘要到期或读取异常不影响正文重放。客户端兼容旧 run.requestId，不丢反馈与历史去重身份。契约已编译，前后端类型检查通过；原请求恢复8项通过（含账号隔离、取消和不重放），持久化无摘要故障新增1项通过。此前当前源码 memory 专项19项通过，不把这次新增项算作对19项的再次执行。
6. B 工具已说明静态/观察证据，但手册及文档站设计页仍残留“独立观察即可建节点”的旧标准。总线程修正四份双语手册与站点设计源稿，关联 C 的完整案例，区分初始估计、上下文压力与硬边界，并明确未知声明与未知扩展字段的不同处理。A 的九篇双语文章和适用 Skills 已关联最终案例。B 续改命令曾因编码错误未生效，总线程依据文件内容识别并改用补丁完成，没有凭退出码宣称完成。
7. E 在目录驱动注册、理解/汇总职责、进展扩额之外，补齐首模型失败的自然交代、同批成功回执保留、网页/飞书历史失败不否决主成果；取消继续终止，发送失败不重放。原两文件25项，闭环三文件31项；最终文案与错误诊断专项18项通过。这些是各阶段证据，不叠加为一次执行的总数。当前没有真实写工具，不把 prepare 命令视作已保存操作。

## 保留的边界

本轮是本地实现与交付物验收，未发布 npm、部署应用或站点、操作生产用户数据、启动 UI 或进行视觉验收。没有验证真实模型语义、真实网络断连、真实外部写入事务或生产可靠率。脚本化用例证明相应路径与边界，不证明模型准确率、性能或成本收益；不把这些证据边界当作尚未实现的本地改造。

Core 没有引入强制业务图、实习助理产品规则或平行调度器。相同质量约束可以由不同架构满足；Banker 与小绽仍有结构差异，验收依据是实际职责、推进、成果、恢复及调用证据，而不是图的形状。
