# Agent Core 技术文章讲解质量整改记录

## 问题与范围

原有九篇文章以原则短段、检查项和外部链接为主。此前同步与引用检查只能证明内容已进入包与站点，不能证明读者能理解推导、比较方案并作出设计决定。本次按讲解文章重写九篇中文及对应英文，保留标题、文章 ID、职责边界与公开实现入口，不修改运行时、版本或发布状态。

## 逐篇内容复核

| 文章 | 贯穿场景及展开内容 | 实现边界 |
| --- | --- | --- |
| nodes-and-tools | 跨查询、比较、检查与导航的任务；成果交接；用例、探索、矩阵选择；拆分的维护与恢复代价 | 图形与节点数不作为质量分数，矩阵工具不等于拓扑边 |
| one-phase-one-declaration | 最终回复阶段仍提出查询；目录同源而阶段投影不同步的原因；准备、测量、发送和实时授权 | 准备快照不冻结业务权限；普通文本案例不冒充工具协议验证 |
| reasonable-dynamic-budgets | 已有资料却因额度无法交付；必要工作估计；具体数字说明总额与余量；进展与扩额 | 保留累计消耗、祖先预留、期限与授权；不虚构费用收益 |
| compression-or-partial | 长历史中的最新纠正；结构数据与自然语言历史差异；四种信息处理方式及部分交付条件 | 确定性投影不是语义摘要；摘要不能授予权限或补足缺失事实 |
| reliable-request-recovery | 成果生成后最终响应失败；业务与交付两条状态；三层恢复；取消、超时、断连 | fallback不依赖模型且仍可能抛错；函数返回不等于送达 |
| targeted-completion-repair | 附属篇幅拒绝导致全工具重跑；修复目标、否决权、顺序与输入范围 | Kit决定与App真实路由分开验证；保存是否主任务依本轮目标判断 |
| evidence-and-operation-receipts | 文件生成后连接断开；读取、答案、操作的身份差异；未知写入核实与重连 | 内存Map不是跨进程幂等；未知不能等同未执行 |
| observe-real-execution | 最后协议错误之前已出现流程偏离；四层证据、时间线、日志范围与复现场景 | 中间预算快照不当最终调用总数；采集缺失不填伪零值 |
| test-completion-under-faults | 单模块通过而组合丢失答案；故障位置、不变量、真实模块组合、预算和压缩反向测试 | 离线、真实模型、生产与视觉证据分别说明 |

目录改为有解释的阅读路径，正文使用连续段落展开原因与选择；对比表只用于确有并列方案的地方。英文同步场景、推理、取舍和实践边界，不只翻译结论。人工内容审校按这些具体要求进行，不用篇幅或标题数量替代讲解质量判断。

## 同步与验证

- 唯一来源仍为 shared/agent-core/articles；既有 sync-articles 生成包内 development/articles，并通过 --check。
- 九篇双语正文与目录的本地相对链接、代码围栏及 diff 格式检查通过。
- Pages generateSite 从当前来源重新生成18篇正文和双语目录，逐篇核对未被本地化改写的正文行及入口，不只检查页面存在。
- 实际 npm pack 使用 ignore-scripts；归档内18篇正文与两个目录逐文件对照当前生成副本。临时归档完成核对后删除。
- API表述对照当前预算评估、Completion Kit、请求恢复实现与手册；案例能力与证据限制对照现有引用入口。没有修改或重跑无关运行时测试。

完成范围是本地文章质量整改、包体和站点来源/生成内容同步。未部署线上文档站或发布 npm，没有将离线案例写成生产性能或真实模型质量证明。
