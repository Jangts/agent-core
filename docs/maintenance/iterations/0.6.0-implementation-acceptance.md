# Agent Core 0.6.0 实施与验收记录

日期：2026-11-12。关联：[计划](0.6.0-iteration-plan.md)、[清单](0.6.0-execution-checklist.md)。本记录区分已实施、已验证和发布前未关闭事项，不替代正式API。

## 实现

1. toolbox 公共授权与单项授权分别复用 maybeAssertion。公共成功后检查取消，再进入单项检查；公共false、true、null及其异步结果均拒绝，不把同步工具强制改成异步。
2. Runner 沿用已有 execution 与 bind。共享宿主没有隐式当前请求，直接读取callCount、totalCallCount、remainingCalls、lastCall、journal和signal会明确拒绝；覆写方法从已有请求execution取绑定，读取与super调用相同的执行统计和取消状态。共享私有内存、构造次数和真实接收者保留。execution描述符保留给Engine接入，不代表一次隐式请求。
3. Reflection 在检查余额之前完成本次绑定；子任务组继续整组绑定。已有请求绑定不会刷新额度，祖先预算、预留、预备句柄及并发保护保持原合同。
4. token计数复用synchronous，误返回Promise的拒绝被消费。measure和invoke均在Provider调用和扣费之前拒绝非法计数。
5. retrievalQueryKey限定为有限JSON数据，逐层拒绝循环、稀疏数组、Date、自定义对象、symbol、函数、非有限数和undefined。对象键顺序不改变身份，数组顺序保留；无循环的重复对象引用可以使用。
6. 本地包与各workspace的agent-core依赖及根锁统一为0.6.0。公开签名未增加新的执行概念；变化是共享宿主的模糊状态读取不再返回误导性的空统计。

## 类型、组织与复用评估

- 严格装饰器fixture补充异步compiler和返回非validator的类型负例；原有缺方法、错误ID／namespace／args及公开入口负例保持。
- 沿用现有assertion／同步检查，不新增授权pipeline。Kit生命周期与Core工具执行分别遵守本来合同，不为形式统一而合并。
- 未给JSON Schema再增加一份TypeScript类型／ID映射；任意parser与原始schema的关联仍由真实运行时校验保证，不宣称已获得完整静态推断。
- 核对Banker和Microcola请求入口后，其显式execution继续有效，无需改动业务处理代码或重新包装应用服务。
- schema共享对象编译一次、Prepared计量复用既有快照，由现有回归验证。未跨请求缓存动态候选、权限、用户输入或collector，未宣称有吞吐／延迟收益。

## 四项应用失败的后续分析

- 材料测试仍要求首轮用户上下文包含正文；当前materialsValue只提供kind／index／name／chars，正文由attachment.read按需读取。应拆成首轮元信息隔离和显式读取后正文可用两个场景，不能恢复首轮全文注入来满足旧断言。该formatter的“材料正文”注释也应同步为元信息。
- 两个未知工具失败具有相同根因：带tools声明的schema在解析时发现name未登记，直接报MODEL_PROTOCOL，尚未进入ToolRegistry。TOOL_UNAVAILABLE仍适用于执行注册器查找不可用工具。应按模型提案与直接执行两个入口分别验证，而非统一替换所有错误码；混合JSON和selector冲突用例应与未知工具断言分开，避免前项失败遮蔽后项。
- 自动导航测试的脚本序列多了一次中间final：当前实际序列是决策→强制授权复核→拒绝后的普通回复。旧脚本把final对象交给复核，再把approved对象交给普通回复，最终落入预置的未执行出口。保留全部安全断言，在隔离诊断副本中只移除错位final并调整调用索引后，用例通过，输出明确“这次没有跳转”；原测试文件未修改。证据为根`.tmp/agent-core-060/four-corrected-analysis.log`。这说明该失败应修正阶段脚本，而非取消强制审查或仅将4改成3；普通回复fixture还应按纯文本交付，避免对字符串无条件JSON编码。

上述分析明确了测试修正方向，但没有关闭原始四项失败；只有正式测试更新并完整复跑后才能变更E03验收状态。
