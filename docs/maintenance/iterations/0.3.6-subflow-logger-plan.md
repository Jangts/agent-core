# 0.3.6 子日志实施与验收记录

## 目标与范围

由绑定执行 context 的 createSubFlowLogger 创建唯一实例，Loop 接管运行期生命周期。write／fix 即时交付 runtime，不通过节点报告或结束回调提交；readAll 仅查询。继续复用 node.progress、内容授权、身份、状态转换与失败隔离机制，不增加业务调度层。

## 实施顺序

1. 子日志变更回调传递不可变快照，runtime 先接收再通知消费者。
2. NodeReports 持有已入账快照；关闭访问后释放 logger，终态事件不读取 logger。
3. 移除报告 subs 字段，工具结果 hook 使用绑定 context 写入，不提交返回值。
4. 同步中英文合同、使用示例、版本与 workspace 依赖。
5. 针对实时修订、错误、取消、访问隔离、元数据隐私与工具入口执行最小回归。

## 解绑与返回值合同补充

write 任意失败返回数字 -1（不使用 -403），fix 任意失败返回 false；解绑等同失败，不读取入参、不修改记录、不发布事件。fix 正常成功返回 true，所有失败（含无效 ID、非法输入和禁止的修订）统一返回 false。readAll 允许任意持有者持续查询；节点实例可保留旧 logger 供下一次执行参考，也可借用给外部，Core 不限制用途。再次访问节点得到新 logger，旧实例不会重新绑定。

## 子节点归集与委托类最终验收

完整 SubFlowLogger 与 ScopedSubFlowLogger 是不继承的独立类，实现共同 SubFlowLog 接口。受限类只持有原 logger 与子节点 ID，无记录存储；其读写委托同一个完整 logger，readAll 读取全量，write 自动补归属，fix 检查目标归属。只有完整类具有 fork 并可作为 invoke 的 logger，静态类型与运行时均拒绝受限／伪造实例进入调用边界。

node 可以直接在 write 填 subnodeId，fork 仅用于固定归属与省写。自定义分组不要求真实分发、连续分段、依赖或调度；应用按实际业务职责使用。注册调用将 node ID、node 访问身份、能力种类、定义 ID 与原有 invocationId 组合为归集 ID，不增加独立调用计数。type 为自由业务类型，operation 专门表示 write／fix；fix 采用独立允许字段清单，不能更改身份、归属、类型和名称。

write 失败为 -1，fix 失败为 false，拒绝不新增记录。开发者控制台使用固定原因输出去重 warn，无正文／补丁值／任意错误文本；控制台异常不改变接口结果。测试覆盖了越组、禁止字段、失效、全量共享读取、metadata getter 隔离、运行时拒绝受限 invoke、真实调用 ID 复用以及安全告警。

最终 Core ESM／CJS 编译与两个后端 TypeScript 编译通过。Core 全量820项、两个后端相关163项通过。公开类型回归包含受限 logger 无 fork、不可传 invoke、不可覆盖 subnodeId、fix 无分组／type 字段。中英文公开参考索引统一从同一个生成器按 --language zh/en 生成。

## 注册子节点 ID 简化

自动分组改为本次 node 内的 kind:encodedDefinitionId:ordinal，原 node 访问身份不重复编码。完整 logger 按 kind/definition 在调用开始时分配计数，包含失败和取消，不复用编号；新 node 访问使用新 store，从1开始。真实调用 ID 独立保留在 relatedInvocationId，write/fix 保持该关联不变。计数为本地同步分配，无需跨实例协调，未引入短 hash。
