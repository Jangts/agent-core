# 执行蓝本

本页说明 Agent Core 与 App 的组织方式。职责依据见[Core、Support 与 Kit](design-layers.md)，实际模块见[模块职责](modules.md)，调用合同见[API 手册](../../packages/agent-core/development/docs/api/README.md)。

## 装配与声明

入口负责依赖装配、请求边界与生命周期。可枚举能力通过集中清单定义名称、约束、关系和 handler 引用，同一声明驱动校验、模型可见投影和分发。固定服务及默认策略在实例上绑定，请求只提供本次变化的数据。

## 编排与执行

Workflow 展示节点、顺序、分支、异常去向和结束条件。handler 负责明确的业务单元；Core 维护模型与工具调用、预算、取消、状态提交及执行事实。普通顺序算法保留普通调用链，不为形式统一强加图或平行框架。

状态更新、授权和副作用各有明确边界。取消、期限或验证失败不能提交迟到结果，已发生的外部副作用不能假装回滚。App 通过真实存储事务和回执实现对账。

## Support 与 Kit

Support 提供符合 Core 接口的推荐实现、场景策略、字段推导与清单生成，可被结构上符合合同的实现替换。Core 不依赖 Support 身份。Kit 由 App 单向选用，拥有自身局部协议；App handler 返回 Core 时遵守 Core 合同。

知识、回答、展示、查询和交付由对应 Kit 组织通用过程。平台字段、用户偏好、权限、提示词和事实源由 App 提供。Kit 调用 Core 时继续服从祖先预算和取消边界。

## 观察与交付

Core 的运行观察与持久日志消费同一执行事实。Support Provider 的网络观察和 Kit 局部观察由 App 收集。实时输出使用按序等待的交付端口，旁路观察失败按观察合同隔离，不能吞掉业务交付错误。

## 接口审查

审查关注真实耦合、重复实现、输入所有权、handler 接收者、同步异步边界、错误归属及消费者接入。共享基础可跨用途复用，不为分类完整新增目录、门禁或执行层。示例、类型声明和真实调用方保持一致。
