# API 一致性设计

接口设计遵守[接口设计规范](../standards/interface-design-standard.md)。其中缺省、复用、代指、渐进配置、公私规则边界及 Support 场景补全共同用于 API 评审。

公开签名、参数、返回和异常以[API 手册](../../packages/agent-core/development/docs/api/README.md)为准。职责关系见[Core、Support 与 Kit](design-layers.md)。

## 构造、绑定与执行

固定依赖和策略由实例持有；请求传递本次变化的数据、取消信号和授权上下文。最小调用与完整配置使用相同入口，逐步补充字段即可扩展能力。Core 接受符合接口的普通对象或实例，保留 handler 的接收者，不要求 Support 实例身份。

Core 的缺省值保障有界基础运行；Support 按明确场景生成推荐参数，精确值可覆盖策略补全。Support 产物直接满足 Core 合同，不需要转换为 plain object。

## 命名与结构

同一概念使用相同字段和数据结构。实体引用、执行身份、时间和计数明确区分；执行时间使用绝对毫秒，外部格式由适配边界转换。输入、定义和运行状态分别持有，不把权限、余额或信号固化到可复用声明。

同一 API 的便捷输入保持统一的返回合同。同步入口拒绝 Promise，异步入口等待真实结果；检查回调按对应合同返回值或抛错，不以未约定的布尔值替代断言。错误保留阶段、原始原因与真实副作用信息。

## 路由与声明生成

原始路由对象是完整配置。route 及其语义方法生成相同配置，不另建执行格式。专用生成器拥有自己的默认 ID 规则；Workflow 处理所有原始配置共同支持的占位符、引用与冲突校验，不把某个生成器的命名习惯作为全局补全规则。

## 运行保证

预算、取消、期限、授权、输入输出校验和错误顺序由实际执行合同保证。模型及工具调用通过相同运行身份关联请求、结果与日志；Journal 是同源事实的请求内投影。App 拥有持久化、保留、披露和真实业务授权。

## 公开面

Core 与 Support 从根入口提供，Kit 使用独立入口。聚合路径引用同一实现，不复制执行逻辑。类型与实现的公开范围可从声明及文档直接确定。示例、真实消费者和文档使用同一合同。
